# NV SCREEN underlay checkpoint

Source: Nightmare Vision `733165c42ca71eb0961a70e4173b2d81ba4a29ea`, PlayState lines 723-729 and 1935-1941. SCREEN is one state-owned overlay, independent of every PlayField. A scene creates it only when its creation preference is Screen Dim, even at zero opacity. Its graphic is a black 1x1 pixel; opacity is copied once, scroll factor is zero, and camera is camHUD. It is added before the first host HUD groups, receptors and notes. FIELD underlay sprites and their modifiers remain separate.

Geometry follows the current public screenDim and its current camera: scale is camera.width/zoom and camera.height/zoom, followed by updateHitbox and global FlxG screenCenter. Script alpha, color, visibility, existence, graphic and camera are retained. Negative zoom retains signed division and Flixel takes absolute scaled dimensions for the hitbox. Ordinary camera zoom zero resolves to FlxCamera.defaultZoom through its setter. The helper adds no camera-angle compensation or extra geometry guards absent from the donor. Viewport offsets and camera angle do not enter the donor centering formula; this uses logical game dimensions, not hardware framebuffer dimensions.

Type changes do not create a late overlay, hide an existing overlay, or reapply opacity. If the type changes away from SCREEN, its existing geometry remains frozen and its state membership remains unchanged. The original added sprite is owned by normal state destruction. Replacing the public reference only changes the geometry update target; it does not auto-add the replacement or destroy the original. A replacement is state-owned only if a script adds it normally.

The geometry update runs once at the ordinary host update tail before source post callbacks, including host outro/custom-substate return tails that the donor update reaches. It is absent from the shared post dispatcher and game-over dispatch, and is not repeated for each fixed-clock catch-up callback. This preserves post-callback sprite changes within a batch; the host fixed source clock itself remains a separately documented source/runtime difference.
