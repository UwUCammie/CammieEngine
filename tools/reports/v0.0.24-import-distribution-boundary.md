# Import distribution boundaries

Local v0.0.24, 10 October 2026. Shared importer change only.

A fresh library of separately imported example packages exposed a general Auto detection failure: a selected download wrapper could contain a supported game directly inside `bin`, but the scanner pruned that directory before inspecting it. The independent fixture's fifteenth import failed with no supported owner. No installed content was replaced by that failed attempt.

The scanner now inspects `bin` and `dist` boundaries beneath unrecognized wrappers. It descends only if the boundary itself matches a supported game root. Recognized game roots still prune nested build output, and unrecognized SDK/build boundaries remain pruned after that single inspection. Normal directory, cancellation and depth limits remain in force. This does not inspect names of songs or mods or modify donor files.

Synthetic tests cover both distribution directory names, casing, recognized-root pruning, unrecognized SDK trees, `.tools`, and explicit selection of a game inside `bin`. A read-only real-download fixture confirms detection and unchanged executable bytes. The previously failing native Auto import then succeeded in the isolated installation and committed its own retained receipt.

The canonical Windows build passed. The full regression run completed 2,764 tests across 931 modules in 376.4 seconds, with 344 environment-dependent skips and no failures. Evidence: `tmp/v24-distribution-build.log`, `tmp/v24-distribution-suite.log`, and `tmp/v24-independent-library/progress.json`. Native tests use a muted, never-activated private desktop. No release or publication.
