# Historical NV receptor pointers and text preset

Development v0.0.23, 9 October 2026. This is a bounded Phase 2 checkpoint, not complete historical NV or chart parity.

## Source contract

Historical Nightmare Vision revision `7f96eb3b5a60352413229bf134bd348b79ad5fe6` declares mutable `playerStrums` and `opponentStrums` PlayField pointers and a fresh flattened `strumLineNotes` getter in `source/meta/states/PlayState.hx`. Pointer identity is independent of mutable IDs and collection order. Its PlayField derives from FlxTypedGroup. A group supplies default draw cameras; explicit child cameras win.

Modern NV uses a different field/container interface. The host native Strumline is a FlxTypedSpriteGroup, whose camera setter propagates to children. Historical group semantics must therefore be selected by authenticated engine API evidence rather than applied to every field.

The historical preset in `source/meta/data/scripts/FunkinHScript.hx` also defines `setTxtFormat(txt, ?Font, Size = 8, Color = WHITE, ?Alignment, ?BorderStyle, BorderColor = TRANSPARENT, EmbeddedFont = true)`. It calls native FlxText.setFormat and returns Void.

## Shared implementation

- Capture the two default source PlayField objects during construction. Bare globals, `game` properties and reflected reads/writes share these pointers. They do not overwrite host native gameplay pointers.
- Return a new flattened receptor array in the current field collection order, including live additions/removals. The getter is read-only through reflection too.
- Select historical camera behavior with the existing imported Stage API profile. Assign group camera defaults through the native line's internal group and preserve explicit child cameras. Clear only the initial host-assigned receptor cameras on first historical admission. Later reconfiguration preserves authored overrides.
- Preserve camera assignments made before line binding and across display attachment. Underlays use the same field camera as the receptors. Modern fields retain the native SpriteGroup camera setter.
- Release captured pointers at scene teardown.
- Expose the source text helper in the shared NV preset and delegate formatting directly to FlxText. No duplicate text renderer or owner asset lookup is added.

No donor or chart edits, song-name conditions, or alternate-mod asset substitutions are involved.

## Remaining contracts

The historical generation sequence differs from modern NV: it constructs both default fields before one zero-argument pre-generation callback, generates opponent then player, and adds opponent then player to the field collection. The current host still uses per-lane callbacks and its existing collection initialization order. The new flattened getter follows the actual collection; it does not claim to fix historical generation order or mod-manager index semantics. These remain an explicit next lifecycle task.

The retained historical package includes flat `shared/images/NOTE_assets` and `noteSplashes` atlases. Historical `Note.hx`, `StrumNote.hx`, `NoteSplash.hx` and `PlayState.hx` use those flat default names. The current owner-aware NoteSkin resolver changes only the omitted sustain-splash default; ordinary notes and splashes still inherit modern `UI/notes/...` defaults. Correct these omitted defaults through source/version selection, preserve every explicit path, and verify owner/core atlas selection before claiming complete note rendering.

Advanced Animate APIs, embedded/custom libraries, the remaining Psych/NV API inventory and full Phase 2 acceptance remain open. All later imported-menu, management, categories/favorites, dense Freeplay, icons/stars, independent sorting and fidelity-preserving performance goals remain in the roadmap.
