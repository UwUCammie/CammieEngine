# Psych shared sprite and text registry

Local v0.0.23 development. Publication remains gated on the full roadmap.

## Source and implementation

Pinned Psych revision `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`: `source/psychlua/FunkinLua.hx`, `FlxAnimateFunctions.hx`, `LuaUtils.hx`, `ModchartSprite.hx` and `ModchartAnimateSprite.hx`.

Modern Lua static sprites, animated sprites, Animate sprites and text now publish into the same gameplay variable registry. The constructors normalize dots and return no value. Ordinary sprite construction reuses the text service's source-ordered replacement. Animate construction retains its distinct kill, main-play-state removal without splicing, destruction, live registry publication and activation order. Source activation runs the native property setter.

Shared sprite transactions support front/behind insertion, the game-over boyfriend anchor, retained removal, explicit group removal and source variable-removal ordering before sprite destruction. The generic removeObject extension delegates to the appropriate sprite or text operation. Historical NV and generic host constructors remain separate. Existence checks distinguish source sprite classes from native text rather than treating every FlxSprite as a Lua sprite.

PsychModchartSprite reuses native FlxSprite rendering and animation, adding the source animOffsets/addOffset/playAnim surface. Native dispatch applies its offsets and optional reverse/start-frame arguments. Asset loading reuses owner-scoped image, frame and Animate loaders. The Animate loader accepts a live object before registry publication, sharing the same implementation with tagged loading. The shared XML frame-name reader preserves authored indexed-animation ordering; modern sprite metadata lives on the object and is invalidated when native frames change, rather than retaining destroyed objects in a registry cache.

The gameplay host can represent actor groups or direct actors. Behind insertion uses native source groups when available and direct actors otherwise. Full source stage construction and transition coverage remains a separate gate.
