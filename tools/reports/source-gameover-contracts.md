## Actor selection, placement, and camera

Both donors borrow the live player actor when its `curCharacter` equals the selected game-over character. Otherwise they construct a death actor at the gameplay BF's screen position, then add the death actor's `positionArray` delta relative to the live BF. Host source modes use the same name comparison and preserve the borrowed actor's ownership: `source/GameOverSubstate.hx:114-136,204-225,928-964`. Destruction detaches a borrowed source BF instead of destroying the PlayState-owned actor.

The initial native setup checks exposed suffix stripping: the expected death-actor identity did not survive construction, and the NV check also observed the wrong or missing death animation. The source-owned constructor now preserves the requested ID, tries its exact visual first, and uses the resolved visual ID for metadata and interpreter loading. Native Psych now verifies `bf-dead` and NV verifies `pico-dead`, followed by loop playback and actual scene handoffs. Missing-definition fallback fidelity is still limited as described below.

## Shared camera reflection boundary

The native Psych probe found `FlxG.camera.followLerp == null` while the compiled `game.camGame.followLerp` was `0.01`. The exposed `PsychFlxCameraCompat` wrapper omitted that native field. Its Iris reads/writes now delegate unlisted camera members to the native camera; explicit filter helpers keep their side effects. The Psych FlxG view similarly delegates unlisted global members, and assigning a saved camera view unwraps it to the native camera. Routes are guarded by `#if flixel` so non-Flixel interpreter fixtures retain their existing dependency boundary.

`test_source_camera_reflection.py` executes the actual Iris boundary with a real FlxCamera and verifies followLerp reads/writes, an unlisted field setter, a method receiver, FlxG autoPause, filters, null camera, and saved camera assignment. The eight native setup runs additionally verify initial follow rate, live camera writes, alpha reads, and a non-null FlxG.stage. Arbitrary typed/tween consumers of the wrapper and complete class-identity parity remain unverified.

Psych starts `firstDeath` before requesting `getGraphicMidpoint()`, uses that graphic midpoint plus `cameraPosition`, resets camera scroll/target, focuses on screen center, and follows at lerp `0.01` (`Psych GameOverSubstate.hx:64-83`). The host uses the same post-animation midpoint and screen-centering order (`source/GameOverSubstate.hx:233-252`).

Nightmare Vision measures `getMidpoint()` before `firstDeath`; its follow point is `(midpoint.x - cameraPosition[0] - 100, midpoint.y + cameraPosition[1] - 100)`, with initial lerp `0` (`NV GameOverSubstate.hx:80-100`). At frame 12 or later it changes follow lerp to `0.02` (`:159-170`). Host NV uses this formula and initial timing (`source/GameOverSubstate.hx:226-252`) and applies the frame-12 threshold in `updateGameoverAnimation()` (`:784-803`).

The extracted setup fixture checks actor reuse, position deltas, midpoint choice/order, and both follow formulas (`tools/tests/test_source_gameover_setup.py`). Psych follows once during setup; the former frame-12 and loop-start follow calls were removed because they overwrote subsequent script camera changes. The fixture now checks that the follow count stays at one through those boundaries. NV retains its authored frame-12 follow. These checks do not establish native camera pixels.

## Source audio, loop timing, and callbacks

Psych resolves the initial death name through `Paths.sound`, the loop through `Paths.music`, and the confirmation name through `Paths.music`. The loop is loaded into the active music handle after `onGameOverStart`; playback starts only when `firstDeath` finishes (`Psych GameOverSubstate.hx:73,85-87,135-150,208-212`). Host uses the captured Psych owner and its stage library for those lookups (`source/PlayState.hx:4284-4319`), preloads after `onGameOverStart` (`source/GameOverSubstate.hx:350-375,259-266`), and starts that same handle after the initial animation completes (`:822-869`). Missing Psych assets currently diagnose and use Flixel's beep; verify this against actual donor asset-failure behavior before claiming missing-file parity.

NV skips a null initial, loop, or confirmation name, but a non-null empty string is still an attempted lookup. Initial audio is `Paths.sound`; loop/end audio use `Paths.music` (`NV GameOverSubstate.hx:93,185-190,200-214`). Host preserves null-vs-empty behavior and resolves through the owner-bound `NightmareVisionPaths` (`source/PlayState.hx:4291-4319`; the path adapter's missing-file beep is in `source/NightmareVisionPaths.hx:232-237,332-344`). It does not substitute Psych's non-null defaults after a script/metadata write of null.

## Psych-only visual branches

When the effective name is exactly `pico-dead`, Psych adds `Pico_Death_Retry`, places it at BF `(+205, -80)`, starts its loop at firstDeath frame 35, and uses the Retry Text Confirm animation/offset `(250, 200)` when confirming. If the gameplay GF is `nene`, Psych also inserts `NeneKnifeToss` behind the actor and destroys the knife after its animation (`Psych GameOverSubstate.hx:89-130,214-229`).

Host contains this bounded Psych-only branch (`source/GameOverSubstate.hx:312-348,891-896`). Its atlases and antialiasing are fetched from the captured song owner (`:268-301`) and it restores the actor animation callback and cleans owned sprites on teardown (`:381-386,928-948`). Extracted setup tests assert atlas owner, stage library, Nene condition, antialiasing, animation threshold and cleanup. Native atlas/rendering verification is pending.

Psych's `SONG.stage == 'tank'` branch starts the loop at volume `0.2`, plays one random `jeffGameover/jeffGameover-1..25` sound at volume `1`, and fades the loop from `0.2` to `1` over four seconds on voice completion if the player has not exited (`Psych GameOverSubstate.hx:177-196`). Host mirrors the stage/dialect branch and resolves the random voice through the owner/stage library (`source/GameOverSubstate.hx:303-310,813-817`). The extracted fixture pins volume, one loop start, and owner path with a deterministic fake random result. The real Tank audio mix/timing is not natively verified. NV has no Tank branch and must use the generic loop.

## Retry, confirmation, and menu return

Confirmation in Psych plays `deathConfirm` if present, otherwise `deathLoop`; NV always requests `deathConfirm`. Both stop loop music, optionally play the end name according to their null/path rules, start a `0.7` second timer, fade black over `2` seconds, and reset/recreate gameplay. Both call `onGameOverConfirm([true])` after scheduling the timer (`Psych GameOverSubstate.hx:214-240`; `NV GameOverSubstate.hx:200-214`). Host retains the animation distinction, the `0.7`/`2` transition and source confirmation timing (`source/GameOverSubstate.hx:881-925`). Extracted setup/lifecycle tests cover animation choice and scheduling/callback order.

For BACK, NV first calls `onGameOverCancel([])` and only exact `STOP_FUNC` blocks the transition; it resets death/cutscene state, routes to Story or Freeplay, then starts freakyMenu (`NV GameOverSubstate.hx:140-152`). Psych has no cancel callback: it resets client ID, hides the current camera, stops music, resets death/cutscene/charting state, calls `Mods.loadTopMod()`, routes to Story/Freeplay, starts freakyMenu, then calls `onGameOverConfirm([false])` (`Psych GameOverSubstate.hx:153-175`).

Current host `sourceBackToMenu()` preserves NV cancel gating and the common reset/route/music behavior; Psych false-confirm runs after menu switch/music (`source/GameOverSubstate.hx:682-724`, `PlayState.sourceGameOverResetForMenu()` at `source/PlayState.hx:21118-21121`). These source-specific Psych effects remain open:

- **`chartingMode`:** host class-property reads explicitly return `false` and there is no paired source setter (`source/PlayState.hx:4059-4063`). Gameplay enters `ChartingState` at `PlayState.hx:19307`; editor test-play creates a new `PlayState` at `ChartingState.hx:1358-1369`. A real play-test-origin value must cross that handoff and be exposed as Psych's mutable static; clearing it only on BACK is not sufficient. NV has no equivalent.
- **Top mod:** Psych's `Mods.loadTopMod()` resets global `currentModDirectory`, then selects the first enabled `modsList.txt` entry (`Psych backend/Mods.hx:229-236`). Host has no equivalent Psych mod-list/current-directory manager. `NightmareVisionModsContext.loadTopMod()` only reapplies the already mounted chart owner's config (`source/NightmareVisionModsContext.hx:218-229`) and forbids switching its owner (`:91-96`); it is not the Psych operation. `ImportedFreeplayCaller` is currently Codename-specific. Do not substitute the outgoing chart owner for the first enabled mod. A faithful implementation needs a real general menu/mod context; Phase 3's selected-owner session/return routing is still open.
- **Discord client ID:** Psych's mutable `clientID` setter restarts its RPC client when changed; `resetClientID()` assigns the default (`Psych backend/Discord.hx:17,125-138`). Host `DiscordClient` has one hard-coded ID and a single title-started worker (`source/Discord.hx:8-61`; `source/TitleState.hx:85-88`), with no mutable-ID/reset API. Calling shutdown then initialize would create a second worker rather than implement donor reset. Current fixed identity already is the host default, but mod-specific identity changes are unsupported. If mutable IDs are added, reset through the existing RPC owner/worker. StoryMenu also does not update menu presence in `create()` (`source/StoryMenuState.hx:83+`) while Freeplay does (`source/FreeplayState.hx:459-460`), so the Game Over presence can linger after a Story return; fix presence at the ordinary menu entry boundary.
- **Camera hide:** The host now mirrors Psych's visibility write before stopping music and switching menus; NV does not receive it. The extracted lifecycle fixture checks that ordering and the dialect difference. Flixel's state switch resets cameras (`.haxelib/flixel/6,1,2/flixel/FlxGame.hx:561-564`), so this is transition-frame behavior. Native transition pixels remain unverified.
- **Multiple owners:** Settings and event calls are scoped to the captured PlayState, but static resolution still prioritizes global `PlayState.instance`. A transition with two concurrent source owners is not covered.

## Acceptance gaps to retain

1. Psych's missing-definition fallback still selects owner-manifest BF instead of explicitly reading shared/core `characters/bf.json`, so complete fallback-definition/constructor parity remains open despite passing the listed source actor-ID checks.
2. Native custom-scene rendering and the borrowed-actor case remain open beyond the isolated Start STOP checks above. Those checks prove default setup suppression, not a complete custom GameOver scene API.
3. Psych chart-editor test-play state carried into imported script reads/writes and cleared when returning to menus.
4. A real global/top-mod and menu-session context, distinct from the outgoing chart's selected owner.
5. Psych mutable Discord client ID/default reset support through one persistent RPC lifecycle, or an explicit fixed-ID limitation; ordinary StoryMenu presence entry is also missing.
6. Native camera comparison for Psych's transition hide and the extra host Psych follow reissues.
7. Multi-owner static GameOver property routing beyond the current single active PlayState assumption.
8. Native confirmation of source owner asset priority, null/missing sound behavior, Nene/Pico animation timing and the Tank loop/voice fade.

Save/settings hashes matched before/after all final native runs (`tmp/source-gameover-setup-save-check.json`, `tmp/source-gameover-stop-save-check.json`). The retained donor trees were clean in the required audit. Complete evidence and source hashes are in `tmp/source-gameover-setup-checkpoint.json`; this package does not complete Phase 2.
