# Historical speed storage and stage baselines

Local v0.0.23 development. Publication still requires the complete roadmap and exit gates.

## Source and change

Pinned historical Nightmare Vision `7f96eb3b5a60352413229bf134bd348b79ad5fe6`, `source/meta/states/PlayState.hx`: the `songSpeed` setter and BF_X/BF_Y, DAD_X/DAD_Y, GF_X/GF_Y fields.

The shared speed setter now retains a historical-profile branch that resizes notes before committing the new speed. It uses the native active-group iterator and the raw pending array, preserving repeated references, callback-time mutation, nested writes and failure ordering. Equal, zero, negative and nonfinite values retain the source behavior. Generated-music gating remains in place. Historical note retirement uses 350/songSpeed without applying the host fixed-rendering target, playback-rate factor or minimum step duration.

Psych's existing filtered/deduplicated resizing and modern NV's existing behavior remain on their previous paths. The change uses the same Note.resizeByRatio implementation, native note group and speed storage; it does not introduce another note or scrolling subsystem.

Six historical coordinate fields now access the existing native stage baseline points. Stage initialization and GF-like character placement therefore use the same storage. Changing a baseline does not immediately move an already created character group. The native probe restores its speed, note queues, generated flag, retirement window and position coordinates, and destroys its disposable note/group once.

All production changes are engine/compatibility rules. No chart/mod-specific branch or donor edit was added.

## Remaining acceptance

This checkpoint covers direct speed writes and baseline fields, not the complete Change Scroll Speed event. Source event defaults, constant-speed early returns, public tween handles, overlapping completion behavior and playback-rate differences still require implementation and comparison. Historical Set Property traversal and raw-value semantics are also pending. Broader initial-character loading, script-visible null GF, ghost/tween APIs, arbitrary graph teardown, legacy FlxBar, modern Animate and authored-scene acceptance remain open.

The native checks use synthetic disposable note transactions in a real historical-profile scene. They do not certify a complete authored speed-event sequence or cutscene. The fixture retains a v0.0.22 version asset; the tested executable is built from local v0.0.23 source. All imported-menu, library/freeplay, sorting and fidelity-preserving performance goals remain in the roadmap. Nothing was pushed or published.
