# Native source-sprite lifecycle checkpoint

Local v0.0.23, 10 October 2026. No push or publication.

## Behavior

Source classes compose their native superclass. A basic group could previously drive source callbacks through a FlxBasic wrapper, but a sprite group required the raw FlxSprite and therefore bypassed those callbacks. Authored classes whose native base is FlxSprite now construct a native FlxSprite adapter with the source owner attached. It retains one set of native graphic, animation, motion and transform fields and uses Flixel's rendering and group operations directly.

Update, draw, animation update, kill, revive and destroy dispatch to the authored class. Lexical native super calls use a nonvirtual entry, so native group calls and direct source calls run the override once and super runs the actual Flixel method. The reproducible HScript-ex patch covers native fallback dispatch and explicit super expressions. Basic groups use the same sprite object, without an additional basic wrapper. Indexed reads and group return values restore the source identity; grow-style basic-group recycling recognizes the native sprite's authored class.

Owner teardown tracks these native sprites and releases their resources. Native destruction is guarded so direct authored super.destroy and later group/scope cleanup do not release resources twice. Authored cleanup errors remain visible after native resource cleanup. This is shared engine/compatibility work; no chart/mod production branches or donor edits were added.

## Open scope

Other native sprite bases (including FlxText), source subclasses of sprite groups, raw member iteration/replacement, sprite-group recycling, additional native helpers and general reentrant/multi-scene teardown remain open. No claim of full subclass or compatibility parity is made. All original imported-menu, management, categories/favorites, dense Freeplay, icon/star, independent sorting and fidelity-preserving performance goals remain required. The full-roadmap release gate is incomplete.
