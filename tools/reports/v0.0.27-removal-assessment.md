# Read-only removal assessment foundation

The engine can assess a complete receipt-validated ownership inventory without deleting anything. It distinguishes selected-only files from surviving shared owners, shared snapshots, and registry contributions. Unknown metadata, active owners, surviving dependencies, invalid paths, absent registry baselines and partial selection of a multi-package transaction block removal. File candidates are advisory and are cleared if inventory validation fails or is cancelled.

The shared registry classifier now recognizes portable path casing consistently, while retaining the actual path spelling for use on disk. The transaction writer supplies the shared lexical managed-assets path gate.

The executable Haxe fixture covers sharing, dependency and active-owner blockers, ambiguous ownership, cancellation, settings protection, traversal and returned-data isolation. Muted private-desktop tests at 60 and unlimited FPS assessed real receipts from generated imports, verified active-owner blocking and unchanged manifests/favorites, and also passed moved-source identity checks. Evidence: `tmp/v27-release-library-proof.json` and its two logs.

This is not an uninstall feature or authorization to delete files. Complete live inventory collection, locking, live-byte revalidation, per-package transaction splitting, archived identity/reinstall recovery, registry reconciliation and a recoverable publication/cleanup transaction remain required before a removal command or UI is exposed. No donor, imported asset, receipt or save was deleted.
