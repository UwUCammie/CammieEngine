# v0.0.27 host Freeplay browser

12 October 2026. Engine-owned menu presentation only; no chart/mod edits.

## Implementation

- Host Freeplay uses aligned two-line cards and a separate details column. Eight
  rows fit the standard 1280x720 logical viewport without holding Shift. Bounded
  pages fill at either end of the library and retain original registry indexes.
- The new row retains the existing Alphabet/capsule identity while using a single
  title text object instead of an animated object per glyph. Song, source, search,
  readiness, difficulty, score, preview and library behavior use the existing
  services. Pending imports stay gray and locked. No output registry is rewritten.
- Labels are bounded before rasterization; the selected title/source have more
  space in the details column. Missing or not-yet-loaded row icons have a deliberate
  placeholder. Completion stars are labeled separately from favorites and are not
  represented as authored difficulty ratings.
- Up/Down, five-row Shift navigation, difficulty controls and Library actions stay
  on the existing input path. Host pages do not zoom with Shift. Imported custom
  menu scopes and Sound Test retain their existing layouts.
- The importer progress card has its own area above details, away from list rows.
  The empty view explains how to recover and suppresses stale chart details.

## Evidence

- Canonical Windows build and full regression suite passed: 2,789 tests across
  938 modules in 394.1 seconds, 344 existing environment/corpus skips, zero failures
  (`tmp/v27-browser-full-test.log`). Final text-policy checks also passed.
- All 28 focused Freeplay checks passed (`tmp/v27-browser-focused.log`), including
  the new 1,300-entry page bounds, beginning/end fill, filtered stable IDs, empty
  selection and bounded-label tests. The initial extracted availability fixture
  lacked the new optional presentation state; it was updated without changing its
  chart-support/launch assertions and then passed.
- Final private-desktop native checks passed at configured 60 FPS and unlimited
  FPS (`tmp/v27-browser-native-final60.log` and
  `tmp/v27-browser-native-finaluncapped.log`). They verified eight bounded host
  rows, actual Up/Down input and page retention, global Favorites/category routes,
  selected difficulty, actual gameplay/pause return, cleared search and empty
  Favorites without a hidden launch. Completion stars are visible above the footer.
- The native long-label capture selects the longest title in the local registry;
  it is not an adversarial maximum-length title. Geometry/label unit tests cover
  longer strings; broader native label and viewport review remains open.
- Existing background import activity kept pending songs gray and locked. These
  runs are functional checks under concurrent regression/import work, not matched
  frame-time, memory or throughput benchmarks. No new performance claim is made.

## Remaining Phase 5 gates

This is a concrete first redesign checkpoint, not completion of the Freeplay phase.
User visual review, physical-controller review, broader viewport captures,
distinguishable same-named owners, authored difficulty-rating presentation and
normal/confirmed icon animation fallback acceptance remain open. Independent
engine filters/group/chart sorting, safe uninstall, source identity recovery and
full imported menu sessions retain their separate roadmap gates.

Nothing was published. Native checks use a muted, never-activated private desktop
and an isolated save restored after the probe; the playing installation is untouched.

## Next shared UI contracts from the local source audit

The Funkin reference separates its capsule title, opponent portrait, favorite
indicator and difficulty label; `SongMenuItem.confirm()` starts the portrait's
`confirm` animation. The new host list adopts aligned metadata and an explicit
focus card rather than copying source artwork. `HealthIcon` currently loads normal,
dying, winning and poisoned atlas prefixes but has no host confirmation contract.
That contract should reuse resolved icon/atlas data and preserve the requested
normal-while-browsing, confirm/winning/losing fallback order. Do not infer animation
availability from a filename or change gameplay health-icon behavior.

The importer already writes `difficultyRatings` into Freeplay entries and chart
metadata (`ModuleFunctions`), but `FreeplayState` currently constructs `SongMetadata`
without retaining that field. The next pass must preserve authored difficulty
names/scale with each rating and resolve the selected difficulty by identity, not
assume an array index equals the global difficulty index. Missing data stays unknown;
`RankStar` continues to represent achieved completion separately.
