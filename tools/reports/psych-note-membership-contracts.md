# Psych pending-note membership safety - historical verified checkpoint

The subsequent live-cursor package supersedes the snapshot implementation described here. See psych-live-note-iteration-contracts.md; receipts below certify the prior membership checkpoint, not the newer pending live-cursor files.

The source Psych gameplay pass now rejects an entry that an earlier callback detached from the active note group without killing or destroying it. Native, Nightmare Vision and Codename routes retain their existing iteration behavior. This is a bounded safety repair, not complete donor mutation-order parity.

Pinned Psych 1.0.4 PlayState:1808-1841 uses a live index loop and increments only while the current note exists. invalidateNote:3125-3129 kills, removes with splice=true and destroys. That handles ordinary current retirement, but a current live detach can still skip its shifted successor. The host retains its reusable entry-list ordering while guarding pending membership.

source/PsychNoteIteration.hx observes the captured group's actual Flixel memberAdded/memberRemoved signals only during the pass. It reuses the existing scratch list and two ObjectMaps. Constructor-bound listener methods avoid per-note closures. The gameplay loop checks membership, exists/alive, group identity and group destruction; cleanup removes live-group listeners, clears retained note/group/signal references, and rethrows gameplay callback failures unchanged. Active reentry is rejected before touching outer storage.

Pinned Flixel 6.1.2 remove signals follow both splice modes; replace removes then adds; clear sets length zero and dispatches old members before clearing the array; destroy destroys signals before members. Existing signal listeners can nest mutations before the helper receives the outer notification. For entries already in the snapshot, live mutation events reconcile against the actual array. Default Note groups have length equal to members.length outside clear; the mismatch during clear marks entries absent. Membership is separate from liveness, so remove/kill/readd/revive and nested dead readd can still visit an eligible original entry.

The ordinary pass is linear, with no per-note indexOf or new snapshot array. Normal killed-note retirement uses a fast absent-membership path without an additional scan. Live detach/readd events and entries added during the same pass can require an array scan: the worst case for m live mutations over n notes is O(n + m*n), in addition to Flixel's own removal searches. Two FlxSignalHandler registrations are allocated per pass; map wrappers and listener closures are reused. This is not a broad performance optimization.
