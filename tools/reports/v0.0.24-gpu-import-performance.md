# v0.0.24 GPU and import performance checkpoint

## Scope

Requested priority: Try Harder GPU cost, then large import/update refresh costs. All production changes are shared engine paths. No authored chart, script, shader asset or mod file was changed. The application remains development v0.0.24; no release is authorized by this performance request. The remaining roadmap goals are unchanged.

## GPU measurement

Machine: Radeon RX 7900 XT, AMD driver 32.0.31041.1004, OpenGL 4.6 compatibility context. Native Windows release build, 1920 x 1080 window, 1280 x 720 authored design space, 60 FPS cap, all shaders/effects enabled, low quality disabled, background/highway dim zero. Gameplay tests used the hard chart, botplay/practice, muted audio, and a never-activated private desktop. No compilation or import benchmark ran alongside the timed GPU sessions.

`CAMMIE_GPU_PROFILE=1` installs a 16-slot nonblocking GL_TIME_ELAPSED query ring around OpenFL rendering, before presentation. Query availability is checked before reading the 64-bit result. This measures GPU elapsed render time, including any GPU command-stream gaps; it is not a hardware utilization counter, CPU update duration, or presentation/vsync time. No glFinish/readback is used in timed runs. The pinned Windows Lime exposes query methods but builds their implementation out unless GLES3 is enabled, so a small opt-in Windows driver bridge is necessary. Unsupported targets explicitly report unavailable.

The generic shader normalizer recognizes a conservative nearest-distance minimum reduction and accumulates squared distances, applying one square root after the loop. It keeps the same coordinates, loop counts and samples. Unsafe running-value reads, ambiguous types, nonliteral initial bounds, macros, function overrides and side-effecting arguments are excluded. `CAMMIE_SHADER_OPTIMIZATIONS=0` provides a diagnostic reference path.

| Matched song interval | Baseline median / p95 GPU ms | Optimized median / p95 GPU ms |
| --- | --- | --- |
| 10-60 seconds | 1.18632 / 1.20268 | 1.17312 / 1.18968 |
| 90-120 seconds | 1.08092 / 1.10412 | 1.06836 / 1.09128 |
| 180-240 seconds | 1.62076 / 1.68176 | 1.60760 / 1.66644 |
| 10-60 seconds, same-binary repeat | 1.18636 / 1.20504 | 1.17340 / 1.19216 |

This is a repeatable but small gain, about 0.8-1.2%, not proof that a slower laptop's severe lag is resolved. The laptop GPU/resolution and a capture from its lagging section remain useful for deciding the next GPU optimization. Do not describe CPU FPS as GPU performance or reduce effect quality to make this result larger.

## Pixel comparison

`RuntimeShaderCompareState`, enabled only by `CAMMIE_SHADER_COMPARE`, renders the reference and candidate side-by-side with identical input dimensions, uniforms and time. The tested procedural shader was read from the private imported fixture; its file was not edited. Six fixed times were rendered: 0, 1, 10, 80, 175 and 230 seconds. Across all six captures, every compared RGB channel was identical. The bottom 30 rows were excluded because the engine's separate MUTED overlay is present only in the right half; 441,600 pixels per image were compared. There was no resolution reduction, sample removal, animation throttling or shader disabling. This demonstrates the sampled output, not every possible shader input.

Evidence: `tmp/v24-gpu-summary.json`, `tmp/compatibility-visual-check/tmp/v24-gpu-{baseline1,optimized1,baseline2,optimized2}.jsonl`, and `tmp/v24-shader-pixels/comparison-without-mute-overlay.json`. The baseline executable was preserved at `tmp/v24-baseline-bin/Funkin.exe`.

## Import acceleration

`ImportSnapshotSha256` now uses one independent Windows CNG SHA-256 stream per hash, with the existing portable implementation on unsupported/unavailable systems. The system library is loaded only from System32; hash handles are closed on completion/failure and have a GC finalizer for abandoned streams. The algorithm provider is shared, while mutable hash state is private per stream. Provider errors after initialization fail the operation rather than skipping verification. This follows the system API's streaming hash and object-lifetime contract ([BCryptCreateHash](https://learn.microsoft.com/en-us/windows/win32/api/bcrypt/nf-bcrypt-bcryptcreatehash)).

This accelerates existing capture, retained-source verification, staging checks, installed-file checks, copy verification and publication rechecks. All bytes are still SHA-256 checked. No receipt/schema revision was bumped: identical import outputs do not require mass reimport just because the application version changed. Pending/uncertain chart locks and gameplay worker pausing are unchanged.

The isolated native benchmark uses 24 synthetic media packages, each with an 8 MiB file and 16 small JSON files: 192 MiB media and 408 installed files total. Both modes use the same binary and existing capture/verify/transaction code. Source data is already in the filesystem cache from fixture creation. This deliberately measures shared I/O/hash stages; it does not claim an end-to-end speedup for conversion, image decoding, discovery or all real mod packs.

| Total across 24 packages | Portable SHA-256 | Native SHA-256 |
| --- | --- | --- |
| Capture | 1.344 s | 0.318 s |
| Retained-source verification | 1.240 s | 0.188 s |
| Initial transactional publication | 4.344 s | 1.309 s |
| Unchanged-output refresh checking/publication | 4.933 s | 0.893 s |

Refresh I/O was 5.52x faster (81.9% less time) in this fixture. Independent Python SHA-256 checks confirmed all 408 installed files were byte-identical, and all 24 retained snapshot identities matched. The native probe also compared both backends against known/reference SHA-256 results at empty, padding-boundary, buffer-boundary and million-byte inputs, including incremental updates. Existing cancellation, conflict and recovery tests remain required.

The first benchmark was discarded: the portable baseline hit a snapshot directory rename failure after 18 packages. A fresh directory completed both modes without errors. This transient failure was not treated as a hashing improvement or used in the timing comparison. Evidence: `tmp/v24-import-bench2/results.json`, `tmp/v24-import-bench2/equivalence.json` and `tmp/compatibility-visual-check/tmp/v24-gpu-importbench2.process.log`.

## Reproduction

Use a private copied runtime and never the playing installation. The existing smoke options select song, difficulty, muted practice/botplay, window size and duration. GPU timings require `CAMMIE_GPU_PROFILE=1`; compare the same intervals with `CAMMIE_SHADER_OPTIMIZATIONS=0` and `1`, using `--smoke-frame-stats --smoke-pacing-only`. Do not mix screenshot readback with timed runs.

For pixel comparison, set `CAMMIE_SHADER_COMPARE` to an existing GLSL file, `CAMMIE_SHADER_COMPARE_OUTPUT` to an explicit diagnostic directory, and `CAMMIE_SHADER_OPTIMIZATIONS=0` for reference normalization. The current comparator uses fixed procedural color uniforms and a 3680 x 2920 input graphic, so adapt test inputs deliberately when checking another shader.

Set `CAMMIE_IMPORT_PERFORMANCE_DIR` to a fresh diagnostic directory to run the standalone 24-package benchmark before the ordinary game state starts. It exits after writing results. Do not run it concurrently with other performance measurements.

## Validation

Windows native build and four muted private-desktop GPU playback sessions passed. Six native shader comparison captures passed. Native digest vectors, threaded capture/verification and 24-package transactional import/refresh passed with identical outputs. The full suite ran 2,748 tests across 923 modules in 363.8 seconds (344 platform/donor skips). Ten extracted portable fixture modules initially lacked the new Windows-only class; platform-gating the native reference restored their portable compilation. All 149 tests in the 15 affected modules subsequently passed, including retained refresh, transaction recovery, source snapshots, portable import fixtures and shader normalization. The final Windows native build passed. The final conservative shader guards produce exactly the same normalized shader bytes as the GPU-tested candidate.

Protected-file verification found 69 of 70 saved hashes unchanged. The sole difference is the private `tmp/compatibility-visual-check/assets/data/options.json`, explicitly configured for 1080p performance testing with dimming off, full shaders and a 60 FPS cap. No playing-install, donor or source-content hash changed. Engine text-policy checks found no prohibited punctuation.
