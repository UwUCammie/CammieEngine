# v0.0.36 release validation

This user-authorized incremental alpha fixes a Freeplay stall during search, adds scripted note mechanic and modchart estimates to the Difficulty Rating, revises Freeplay detail presentation and stops repeated automatic refreshes of an import that cannot be refreshed. It does not close broader compatibility, imported-menu fidelity, physical-controller, additional viewport or whole-import performance roadmap gates.

## Build and regression evidence

The final Windows build completed successfully. Its executable SHA-256 is `333d29c6a8c07c615ce1d8bd1598b4596480e85f0d499551ea34d95f7ccabebc`.

The full suite executed 2,881 tests across 978 modules in 411 seconds with 347 fixture/platform skips and zero failed modules, through `run.bat package`. An earlier full run had one failed module: the mixed Auto import fixture copied `ChartDifficultyAnalysis.hx` without its new `ChartMechanicScan.hx` dependency. The fixture list was corrected and the complete suite was run again; the clean result above is that second run, not a scoped retry. The import refresh manager's density expectation was also updated from analysis version 7 to 8.

## Freeplay search stall

The stall was reproduced on the published v0.0.35 build with a private save and muted audio: with search text active the menu stopped responding for 19 to 40 seconds shortly after a song preview began. Native stacks showed the main thread inside a garbage collection releasing native allocations, and process memory had grown by roughly 1 GB. The cause was `FreeplayState.searchNorm` compiling a regular expression for every song on every frame. The replacement performs the same normalization without one, and its equivalence is covered by the search and UX unit checks.

This build was not confirmed natively with a matching search and a playing preview. One native run held an active, non-matching search for 65 seconds at over 2,000 frames per second, compared with roughly 400 on v0.0.35, with a worst frame gap of 128 ms; no preview loaded in that run. Treat the stall as fixed by cause and unit evidence, with native confirmation of the exact reported sequence still outstanding.

## Difficulty Rating

Retained note type scripts and song scripts are read as text and never executed. Unit checks cover classification by code shape in Haxe and Lua, comment handling, the bounded modchart estimate, the rule that script context never lowers a rating, and the refresh pass reading scripts only from a receipt-confined imported owner. Against one imported package, a chart's 67 avoidable input-lock notes, previously counted as ordinary notes, moved its hard rating from 10.39 to 16.34. Two charts of one song with similar heavy modcharts kept their order because the higher-rated chart is denser in notes. Estimates are static and are labelled as such in the details.

Newly converted charts are rated again by the readiness pass after their owner tree is published, so script context applies to fresh imports as well as existing ones. Existing imports migrate through the derived-analysis refresh without reconversion.

## Freeplay presentation

Layout and motion rules for the detail cards and the star stream are unit checked. One native framebuffer confirmed the three backed detail cards in the empty-search state. The visualizer floor and the star stream were not inspected natively in this build.

## Import refresh failures

Unit checks cover the failure marker lifecycle, its invalidation by a changed receipt, importer revision or application version, folded and bounded reasons, and the engine mismatch rule, which requires an explicit recorded type, no recorded evidence and executable proof. A read-only run of the detection against a real outdated import recorded as one engine identified its executable as another and named the correctly detected installed copy. The automatic path was not exercised natively. A mismatched import is reported and no longer retried; it is not migrated automatically.
