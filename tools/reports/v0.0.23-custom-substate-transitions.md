# Psych mounted custom-substate transitions

Local v0.0.23 development. Full-roadmap publication remains gated.

## Shared source changes

Pinned Psych revision `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`, PlayState openSubState/closeSubState and CustomSubstate lifecycle methods. Modern Psych pauses every unfinished global timer and tween and reactivates every unfinished task when closing, including previously inactive tasks. The host previously handled selected timers/tweens or a historical snapshot. SourcePauseTasks now implements the common native task operation; modern Psych source profiles and native source custom substates use it through PlayState. Historical owner-clock substates retain their existing snapshot behavior.

Modern close now requests native closure before the compiled-stage callback, applies canResync, restores global tasks before onResume, and uses the existing shared Psych family broadcaster. Base, historical and other compatibility behavior keeps its existing route. No donor or production chart/mod-specific edits.

## Validation scope

An exact pinned-source task oracle compares all 512 combinations of active/finished flags across timers and tweens for pause and resume, including mutation order. The mounted native probe runs across actual postUpdate frames on PlayState. It requests an open, replaces an uncreated queued target, pauses the real parent and audio, allows menu-created timers and substate callbacks to run, replaces the mounted substate, and closes it. It checks native parent attachment, source static-name ordering, countdown/global tasks, audio, child destruction and a retained registry reference.

The static-name behavior during replacement is deliberately source-derived: construction publishes the replacement name before old-state destruction clears the static name. It is not rewritten around a test name or given a chart-specific workaround.

The probe preserves the disposable runtime's original script maps, variable map, countdown pointer, task activation states and display flags after completion. Testing uses the private muted desktop, never the playing installation. It does not claim complete parent-state teardown, nested custom substates, every source base-substate API, or authored imported menu acceptance. Those and all previous compatibility/menu/library/UI/performance gates remain required.

## Checkpoint results

The initial canonical Windows build and both muted native runs (60 FPS and uncapped) passed the mounted transition assertions. The full suite ran 2,720 tests across 900 modules in 382.3 seconds, with 344 skips and two close-order failures. Those regressions exposed pre-close notification ordering for Nightmare Vision and Codename in the new source path. Both notifications now precede native closure; the source compiled-stage callback still runs before resumption. All 15 affected source/custom-substate/Codename/NV tests pass after these corrections (`tmp/v23-custom-transitions-final-focused.log`). Final canonical Windows build passed. The final full suite passed 2,720 tests across 900 modules in 339.5 seconds, with 344 skips and zero failures (`tmp/v23-custom-transitions-full-suite-final.log`). Both corrected-binary private muted native runs passed at 60 FPS and uncapped, including eight real frames of mounted lifecycle transitions, with reviewed captures and matching executable hashes (`tmp/v23-custom-transitions-native-proof.json`). All 70 protected-file hashes and the engine text policy passed (`tmp/v23-custom-transitions-protected.json`).

The next checkpoint is parent-state teardown with a mounted substate and a different queued replacement. Current parent teardown tracks the pending adapter field, which can differ from the mounted native child. This is an identified audit gap, not a verified fix. Nested substates, inherited timing/control APIs and later roadmap goals remain open.
