# v0.0.27 independent library sorting

12 October 2026. Shared host menu/library layer only; no imported content edits.

## Contract and implementation

Phase 6 now has independent persistent controls for grouping (flat/mod/engine),
group order (default/A-Z/Z-A/engine), and chart order (default/A-Z/Z-A/favorites).
Library actions exposes these controls only in the host browser. Imported custom
menu scopes retain their existing authored order and presentation.

LibrarySort orders original registry indexes, not song/icon/score arrays. Groups
stay contiguous, with chart ordering local to each group. Flat lists ignore group
order. Random Song remains an action at the front, outside package groups. Missing
names/engine metadata sort last in both alphabetic directions; stable owner/chart
IDs break ties. Engine grouping uses preserved sourceEngine provenance, not a
package title. An unresolved imported owner stays separate from base content.

Default order uses the current registry sequence. Generated All lists retain the
pre-alphabetization ordinal on detached presentation copies; the registry itself
is unchanged. Explicit donor week/order metadata beyond the current registry and
first-discovery fallback remains an acceptance task, not an invented ordering.

UserLibraryData adds optional validated sorting fields to the existing version-one
save. Older saves use flat/A-Z, preserving the existing general presentation.
Changes use UserLibrary's existing transactional save and failure reporting.
Full retained chart/owner keys, favorites, categories and named difficulties are
unchanged. Group order is visibly marked inactive in flat mode, but its saved
choice remains available when grouping is enabled again.

The selected original index and named difficulty survive sorting. Keyboard movement
uses the ordered, filtered index view; readiness/launch still use the same existing
authoritative services. Group captions and thin row dividers identify boundaries.
Only the bounded page is materialized. The ordering cache is independent of search;
row reconciliation, sorting preference changes and favorite transactions invalidate
it. Flat title/default sorting adds no provenance traversal. Grouping resolves
existing lazy identity/receipt metadata once per state as needed; this pass makes
no measured large-library startup or throughput claim.

## Validation

Focused compiled Haxe tests pass for independent ordering, ties, missing metadata,
5,000 rows, legacy save migration, invalid preference rejection, detached registry
ordinals, and nonmutating metadata. An extracted production browser method also
passes provenance-based engine grouping, cached navigation, search/filter ordering,
favorite transaction invalidation and row-removal index checks.

The canonical Windows build and full regression suite passed: 2,795 tests across
942 modules in 404.3 seconds, 344 existing environment/fixture skips, zero failures.
The final legacy sort-editor boundary adjustment passed all three related ordering
tests; the final Windows rebuild passed. No repeated full corpus was needed for
that narrow presentation-copy guard or the native probe index-selection updates.

Final muted, never-activated private-desktop runs passed at 60 and unlimited FPS.
The real controls changed mod/group/chart preferences independently. Native checks
confirmed stable selected chart/difficulty, unchanged import readiness, contiguous
groups, bounded rows, keyboard navigation in sorted order, category/badge filtering
and preferences reloaded from the isolated save. Existing global favorites,
gameplay return, named difficulty, icon confirmation and package-badge checks also
passed. Private settings/saves were restored and no game process remains.
