# Historical Nightmare Vision ColorSwap and animation API audit

Development v0.0.22, following published v0.0.21. This checkpoint changes only the compatibility layer and its verification; no new release is published.

## Source and shared implementation

Historical NV revision `54c53faa9493b1de88051fda7fcb7ff69e4f3950`, `source/gameObjects/shader/ColorSwap.hx`, defines a three-component `uTime` uniform, `daAlpha`, `flash` and `awesomeOutline`. Modern NV uses separate scalar uniforms, clamps the saturation adjustment instead of the resulting saturation, and has no historical outline branch. A class-name alias would therefore change source behavior.

`NightmareVisionLegacyColorSwap` preserves the historical setters, defaults and GLSL effect operations. Same-value setters still synchronize uniforms after direct source edits. Its shader uses the existing Flixel texture/color-transform header and renderer instead of copying old vertex and texture-sampling plumbing. The distinct historical effect is kept separate from the existing modern shader because these are genuine source-contract differences, not chart conditions.

The common NV script preset binds the historical qualified class plus both Haxe shader subtype paths. `addHaxeLibrary`, normal imports and scoped `Type.resolveClass`/`Type.createInstance` reuse the existing interpreter and class registry. Explicit legacy imports do not alter another owner's preset. The default bare ColorSwap remains modern; automatic historical preset selection is not established by this change. A future Psych ColorSwap port should share the vector-control behavior where verified against its source rather than introducing another independent implementation.

No chart or mod name selects production behavior. No donor files, manual asset aliases, importer revision or receipt data changed for this runtime API addition.

## Verification

Five focused checks passed, including exact comparison of the historical GLSL effect operations against the pinned donor, real interpreter construction/import/reflection, independent shader instances, uniform writes and restoration, teardown isolation, and unchanged modern shader controls/source. Interpreter checks run with and without position metadata. The uniform fixtures do not execute a GPU.

The first native build caught OpenFL's requirement that shader constructors have block bodies; that was corrected. The final canonical Windows build passed: `tmp/v22-legacy-color-build-final.log`. Executable SHA256: `ab8a1689f545a3e6a705866eabdf61bff85986f5f9d25c29e522a8af79642691`.

The broad suite ran 2,569 tests across 839 modules in 251.7 seconds, with 344 skips and one failed module. The importer manager module failed in setup while writing a Windows fixture-cache lock byte; it did not reach its full test set. See `tmp/v22-legacy-color-tests.log`. The isolated complete-module retry passed all 65 tests in 56.346 seconds (`tmp/v22-legacy-color-manager-recheck.log`). All modules therefore have passing evidence across the broad run and isolated retry. Do not describe the broad run as zero failures.

Normal Freeplay startup checks at 60 and unlimited FPS exited successfully on a private Windows desktop that was never activated. Both were muted, and both framebuffer captures were reviewed. Logs: `tmp/v22-legacy-color-native-60.log`, `tmp/v22-legacy-color-native-0.log`; detailed process/readback artifacts: `tmp/v21-legacy-nv-final/tmp/v22-legacy-color-*`. The unresolved historical ColorSwap diagnostic is absent. FlxAnimate remains unknown during onCreatePost, and downstream video playback still reports invalid access during onSongStart. These bounded startup checks do not certify every shader parameter/outline pixel or full chart fidelity.

All seventy protected donor/playing-installation/save hashes are unchanged, and the text policy passes (`tmp/v22-legacy-color-protected-final.json`).

## Historical animation source inventory and next contract

Follow-up: the official published archive was retrieved and its key implementation files verified in the [historical Animate checkpoint](v0.0.22-legacy-animate.md). That checkpoint supersedes the archive-access limitation below.

The old NV Project.xml pins flxanimate 3.0.4. Its public [release documentation](https://lib.haxe.org/p/flxanimate/3.0.4/) and the [upstream release-era source commit](https://github.com/Dot-Stuff/flxanimate/commit/2332e76e8773d2090ce41a41e52740ebc7466d0f) disagree on addBySymbol argument ordering. The commit explicitly describes 3.0.4, but the published Haxelib archive returned HTTP 403, so it is not verified as byte-identical to that published archive. Reference source was downloaded only into ignored tmp; no library was installed or replaced. Archive SHA256: `931d61cad217ce244879ce224450521ece5c9c84b2ffbe654399a06b8b68e1ac`.

The source declares `addBySymbol(Name, SymbolName, FrameRate=0, Looped=true, X=0, Y=0)`. The README places X/Y before FrameRate. Follow verified source contracts and retain this provenance limitation; do not reinterpret arguments to fit a particular chart.

The next adapter must map onto the existing Animate renderer and owner-scoped asset services while covering:

- Full assets-relative atlas paths, authenticated package/core resolution, reload and released-owner rejection.
- Metadata FPS when a named definition uses zero; legacy prefix matching and trailing-backslash exact matching; per-instance X/Y transforms rather than flip flags.
- Pause/stop/reverse/frame semantics, completion callback (not the modern signal), frame stepping and single completion delivery at 60/unlimited FPS.
- Source stage/current instances, symbols, frame labels and mutable timeline APIs, with explicit unsupported diagnostics until behavior is implemented.
- Settings, pivot/button behavior, constructor/reflection/captured methods, draw bounds and teardown without mutating shared atlas state.

A bare alias to the installed renderer would misinterpret calls and is deliberately not counted as support. Historical video constructors and default note/hold/splash asset layout also remain open. Legacy Stage Lua construction and broader source-controlled mounting/cancellation remain open.

Phase 2 is incomplete. Imported title/main/freeplay/gameplay flows, mod management, categories/favorites, dense Freeplay with proper icons/stars, independent group/chart sorting and quality-preserving performance remain required.
