# Nightmare Vision Alphabet integration contracts

Development v0.0.16 installs actual NV Alphabet and AlphaCharacter classes through the common NV preset. Core glyph/layout comparisons are documented in nv-alphabet-contracts.md. This checkpoint does not complete all source UI, menus or Phase 2.

## Source and routes

Pinned NightmareVision source/funkin/objects/Alphabet.hx declares Alphabet(x,y,text='',bold=false,textSize=1), secondary AlphaCharacter(x,y,textSize), and writable static alphabet/numbers/symbols strings at lines 343-347. FunkinScript.preset seeds Alphabet at source/funkin/scripts/FunkinScript.hx:359. Source static strings have process lifetime; owner isolation and reset below are the engine's explicit imported-owner boundary, not a claim that the donor resets those fields on mod changes.

NightmareVisionAlphabetBindings installs actual class values and factories through SourceNativeClassScope. The Haxe primary import is funkin.objects.Alphabet; AlphaCharacter's Haxe secondary import is funkin.objects.Alphabet.AlphaCharacter, while its canonical runtime class name is funkin.objects.AlphaCharacter. Type.getClass/Std.isOfType retain real identities, and Type.getClassName/resolveClass round trip the registered source spelling. Actual static schemas retain the three declared writable fields. No bare alphabet/numbers/symbols globals are created.

The installer is called from seedNightmareVisionCommon before source owner installation and script execution. Gameplay and persistent plugin seeding both call that common method; gameover and source substates receive the same existing runtime seeding path. No second interpreter or game-owned scope was introduced. Explicit Reflect/Type imports are bound locally, and direct reads/writes, Reflect.field/getProperty/setField/setProperty/copy, resolved std Class methods, extracted callables and Type.createInstance use the same actual classes and owner metadata.

## Owner lifecycle

NightmareVisionAlphabetRegistry keys contexts by captured paths.root. Same primary-owner retries preserve all three authored strings, including explicit null. Different roots have independent contexts even though their actual imported Class values are identical. Scope setup rebinds the shared owner IO provider; reads, writes and constructors do not rebind or reset it. The atlas closure captures only the owner's typed NightmareVisionPaths and calls getSparrowAtlas('alphabet'), using its existing selected owner/__nmv_core resolution. No Psych atlas, host native font fallback, metadata loader or automatic reveal timer was added.

The primary lease hook is immediately after NightmareVisionPluginHost.releaseOtherOwner(root) in initializeNightmareVisionScripts, before the existing mods/prefs owner checks and empty-root return. This permits old plugin onDestroy callbacks to use the old context's atlas until teardown returns. A changed primary root, or empty/null exit, then releases atlas IO and resets the registry. Individual interpreter release clears only that scope's bindings, leaving other scopes and metadata intact. This follows the existing NV owner lifetime; it is not a new global session model.

## Limits

The five inherited FlxMacro convenience methods, full dialogue/menu integration, arbitrary interpreted subclasses and historical parent-library parity remain outside this package. Alphabet.dialogueSound is unused in this source class; this report does not infer letter-sound behavior. Type.createEmptyInstance still delegates native constructor bypass without an owner/context association; no speculative initialization is added. Extra host-private context fields remain visible to native instance introspection. Direct unscoped native construction needs its explicit host owner context; the verified source routes supply it through real factories. Existing NV Paths/cache behavior is retained rather than claimed as fully ported by this binder.
