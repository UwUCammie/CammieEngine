# Selected-owner streaming music leases

OpenFL 9.5.2's `Assets.getMusic` opens a native Vorbis stream from `getPath(id)`, wraps it with `AudioBuffer.fromVorbisFile`, and returns a `Sound`. The decoder keeps the file open while the sound's audio buffer remains live. On Windows, replacing that imported file during refresh can therefore fail even though the old gameplay sound is still valid.

For receipt-verified selected-owner MUSIC-compatible entries on the native Vorbis path, `PsychOwnerMusicStreamLease` copies the exact owner file into a per-process directory below `System.applicationStorageDirectory`, then opens the copy. Lime's SOUND and MUSIC types are aliases for lookup, and OpenFL `getMusic` is path-based, so a SOUND-declared OGG is eligible too. The file is named by a SHA-256 key that already binds the owner proof, asset identity, and content hash. Keeping the content hash out of the filename avoids a second copy of that digest and keeps the native path below the CRT path limit in the tested runtime. The source file is copied and SHA-256 checked in 64 KiB chunks, with source size and modification time checked before and after. A temporary file is atomically renamed only after verification. `Assets.getPath`, the identity index, and the runtime list continue to refer to the installed owner asset. A live stream keeps Lime's ordinary `AudioBuffer` and `Sound` objects; the lease manager tracks the buffer weakly and never disposes it.

The first request pays for one streaming copy and hash. Later requests for the same still-current identity reuse that in-memory verified lease when its size and modification time are unchanged. This is a private cache fast path, not protection against deliberate same-user tampering that restores both metadata values. A new owner proof gets a different lease key, so a refresh can replace the installed file while existing sounds continue from their original bytes. Failed decoder opens are recorded before opening and queued for cleanup. Retirement checks one file per timer step, retries live or locked files after a delay, and an application-exit hook attempts to remove only files in this process's own session directory. It does not clear audio buffers or delete another session's files.

Private session directories left by a process crash are not scanned or removed automatically. A safe cross-process ownership check is not available in this bounded change, and deleting another live process's lease would break playback.

The focused eval checks verified-copy reuse, receipt hash rejection, tamper detection, path containment, and removal of an unreferenced retired lease. The owner-library view and lifecycle eval modules also pass, four tests total. The native acceptance log `C:/t/cammie-owner-library-v19-release-verified/tmp/owner-library-51198b25feb2.log` reports `verified: true` for executable SHA-256 `45dde13375c60d0bb9c5b227bc125816891b8fd71d28141aedb3ca308229857d`. Its Windows-target retained-import fixture verifies Vorbis streaming for both MUSIC-declared and SOUND-declared OGG IDs, preserves the old stream's PCM while a same-path owner refresh publishes changed bytes, and verifies the new stream against those bytes. The report is scoped to this fixture's owner library and refresh path; it does not claim broad OpenFL bootstrap or custom-library parity.
