# Psych text construction and registry lifecycle

Local v0.0.23 development. The full-roadmap publication gate remains unchanged.

## Source contract and shared implementation

Pinned Psych source: `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`, `source/psychlua/TextFunctions.hx`, `source/psychlua/LuaUtils.hx` and `source/backend/MusicBeatState.hx`.

Modern Lua text now uses the host's Psych variable registry, which is already exposed as `variables` and through getVar/setVar. Construction strips dots from the tag, replaces destroyable objects through the active scene, returns no value, and creates a native FlxText with source optional arguments. The shared SourceTextDefaults applies the matching font, size, white color, centered alignment, black outline, HUD camera, zero scroll factor and border size. Historical SourceModchartText uses the same formatter and retains its source-specific wasAdded flag and unconditional camera assignment.

SourceScriptTextLifecycle supports both existing historical transactions and modern variable-registry transactions. Modern replacement and removal capture the variable map before native callbacks. Construction publishes into the live map after creation. Add targets the game/game-over scene even when a custom substate exists. Removal prefers the custom substate, supports non-destructive reuse, and removes before destroying without a preceding kill. The existing generic removeObject extension delegates modern text removal to the same transaction and preserves its original fallback for other tags. Historical behavior is unchanged and keeps its distinct lookup, mounting flag and live-map rules.

This implements the gameplay host adapter. Full MusicBeatState class/static exposure and menu-state variable ownership are not claimed by the host registry. Cross-kind ownership for sprite constructors still needs a shared-registry audit; this checkpoint does not merge or silently fall back to legacy sprite tags. No chart/mod condition or donor edit was added.
