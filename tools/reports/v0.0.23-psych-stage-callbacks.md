# Shared Psych stage callback checkpoint

Development version: 0.0.23, local only.
Pinned source: Psych 1.0.4, revision `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`, `backend/MusicBeatState.hx`, `backend/BaseStage.hx` and `states/PlayState.hx`.

## Change

Source states expose the writable stage list and ordered stage callbacks. Shared iteration preserves live array mutation, captures the array being traversed, skips null/inactive/nonexistent entries and publishes only the matching stage timing fields immediately before callbacks. Psych stages retain writable zero-initialized step, beat, fractional and section values rather than reading host state continuously.

The compiled stage adapter now inherits native FlxBasic lifecycle. Its selected source class object is registered before the runtime's deferred create callback. Public stage-list identity is retained; source-class field access and calls share the same adapter with native stage objects. Gameplay dispatch walks the shared list once, preserving the selected compiled runtime's error reporting and owner cleanup. Source state clocks use the same callbacks. Stage update, gameplay events and teardown honor exists/active gates without treating inactivity as a runtime failure.

Compiled-stage fractional values use the shared Psych clock before gameplay step/beat dispatch. The host integer catch-up cursor and NV modifier clock remain distinct. Construction-to-gameplay scene placement advances even when createPost is skipped for an inactive stage. Runtime cleanup still releases its owned interpreter and retires its native adapter, including when authored destruction is skipped; this is explicit host resource management.

## Verification scope

The native probe uses a temporary authored test class in the disposable runtime and dispatches it through the actual PlayState stage list.
