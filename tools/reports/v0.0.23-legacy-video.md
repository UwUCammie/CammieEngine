# Historical Nightmare Vision video checkpoint

Development version: v0.0.23. Release v0.0.22 is already published; this work is not included in that artifact.

## Work package and source contract

The retained historical package reached `new PsychVideoSprite()` and failed before its opening video could load. Implement the historical API at the compatibility boundary using the existing video renderer, decoder, owner path resolver and state lifecycle.

Authoritative local Nightmare Vision source: commit `7f96eb3b5a60352413229bf134bd348b79ad5fe6`, `source/gameObjects/PsychVideoSprite.hx`.

| Source interface | Implementation |
| --- | --- |
| `new(destroyOnUse = true)` | Boolean constructor over the shared video sprite at (0, 0). End destruction listener is installed at construction, matching the source even if the public flag changes later. |
| `load(location, options)` | Shared selected-owner resolution and pinned hxvlc decoder. Retain the requested path only on successful load. |
| `addCallback(name, callback)` | `onEnd`, `onStart`, `onFormat` attach to decoder end, opening and format signals. Unknown names/null callbacks do nothing, as in the source. No synthesized late callback or error completion. |
| `restart(options)` | Reload the last accepted path with caller options and play. |
| `looping`, `muted` | Shared source option strings. |
| `pause`, `resume` | Shared decoder methods, with the historical explicit-pause focus behavior mapped to pinned hxvlc focus handlers. |
| `heldVideos`, `globalPause`, `globalResume` | Live source registry and methods scoped to the calling script's mod and state, including reflected access. |
| `initializeSkip()` | Empty in this historical source; preserved as such. |
| `VidCallbacks` | Source string constants through qualified and bare imports. |

The modern `funkin.video.FunkinVideoSprite` constructor is different and retains its existing binding. Reusable shared sprites reset format/completion state for each accepted new path. The legacy adapter shares the existing `pauseForState`, `resumeForState` and `destroyForState` host integration; it adds no second lifecycle dispatch.

Private constructor leases opt into replacement/unbind cleanup. Other factories retain their existing shared-owner behavior. An interpreter reinstall cannot accumulate retained empty video registries.

`RuntimeLegacyVideoProbe` is opt-in under `CAMMIE_LEGACY_VIDEO_SMOKE=1` and the normal smoke harness. It requires muted sound and isolated saves. Two generated owner directories hold copies of a read-only 11.133-second fixture. Production interpreter constructors and reflected static controls create and operate the actual hxvlc decoders. The probe does not modify or override a chart.

The first probe incorrectly expected a new format signal after reloading an equal-size clip and timed out at phase 5. Pinned hxvlc reuses that texture; its source event contract does not promise a format callback per restart. The corrected check observes the decoder clock reset, native opening/end events and actual playback. Both runs record three opening events, one format event and one end event. No artificial callback was added to production code.

Reproducible command (run each FPS value separately, with a disposable extracted runtime below checkout `tmp`):

```powershell
python tools/check_legacy_video_native.py --runtime tmp/video-runtime --clip C:/path/to/fixture.mp4 --fps 60
python tools/check_legacy_video_native.py --runtime tmp/video-runtime --clip C:/path/to/fixture.mp4 --fps 0
```

The runner never activates its private desktop. It rejects paths outside checkout `tmp`, verifies generated destinations cannot escape the runtime, restores its options file, terminates only its own probe process on failure, and records the executable/fixture SHA256 alongside the native assertions. An executable regression verifies a playing-style install outside the fixture root remains byte-for-byte unchanged after rejection.

## Historical receptor contract found during this gate

The same pinned historical NV revision declares `playerStrums` and `opponentStrums` as mutable `PlayField` pointers in `source/meta/states/PlayState.hx`. They are assigned during default field construction and exposed to HScript after generation. They must keep object identity if the field's ID changes or the collection is reordered. Its `strumLineNotes` getter returns a fresh flattened array in `playFields.members` order, not the host's native combined FlxGroup.

Historical `PlayField` extends `FlxTypedGroup<StrumNote>`. Its group camera supplies the draw default while an explicitly assigned child camera wins. The host's `Strumline` extends `FlxTypedSpriteGroup`, whose camera setter instead rewrites child camera assignments. Therefore a correct shared field adapter must preserve group inheritance, explicit per-receptor overrides, newly generated receptors and ordinary native/Psych behavior. Relevant seams are `createNightmareVisionDefaultField`, `nightmareVisionConfigureFieldReceptors`, `attachNightmareVisionFieldDisplay`, `NightmareVisionPlayFieldView` and `Strumline.draw`. Implement source-selected live field bindings, not a name-only alias to the host line or an ID lookup that changes the bound object. This research is not implemented receptor parity.
