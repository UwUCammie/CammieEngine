# Import refresh notification lifecycle

Automatic menu instances present active background progress only. The optional backgroundBusy snapshot separates automatic worker/inspection/handoff progress from manual import active navigation gates; Import Settings feeds its manual scan/import status into the same card renderer. Legacy snapshots without the field fall back to busy. Each instance has an explicit owning FlxState and is visible only while that state is current, active, exists and has no substate. Departed/modal states hide it and stop polling it; reentry forces a fresh snapshot. Success, complete and blocked idle snapshots never show a toast, even on a newly constructed screen. The previous per-instance completion timer was removed, so persistent coordinator fields cannot rearm popups after screen changes. Normal progress/text polling remains four times per second.

Coordinator complete/changed/blocked snapshots remain stable and idempotent for existing callers, including smoke completion checks and multiple browsers. Main-thread registry handoff happens once; the returned snapshot becomes idle only after successful handoff. A handoff exception is recorded and rethrown without advancing generation. Transactions/conflict checks, files and retry/input gates are unchanged.

Full diagnostic strings are retained separately, with lock-protected copy-returning diagnostics/count APIs. Repeated identical warnings do not accumulate duplicate text. Import Settings prepends those warnings to its existing manually wrapped, paged detail panel, including before a completed scan exists, and refreshes when the count changes. Scan/import results and their diagnostics stay separate; warning text is not shortened or erased to hide the automatic panel. Existing trace/error logs and manual result screens remain available.
