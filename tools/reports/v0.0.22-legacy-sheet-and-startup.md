## General legacy sprite API

Historical NV revision `54c53faa9493b1de88051fda7fcb7ff69e4f3950` provides `source/gameObjects/SpriteFromSheet.hx`; its FunkinHScript preset registers the short class name. The adapter is available as both SpriteFromSheet and gameObjects.SpriteFromSheet, including owner-local Type resolution/construction. It extends the shared NV sprite base, captures its selected Paths before atlas IO and reads the owner's current antialiasing preference during construction. It does not add image aliases or chart checks.

Constructor behavior matches the historical source: Sparrow atlas, animation prefix/name equality, Flixel's default animation rate and looping, immediate playback, source coordinates and antialiasing. adjust replaces the animation definition and optionally restarts it. Released owner factories reject further asset IO; ordinary sprite destruction uses existing cleanup.

One explicit source defect is repaired: historical play(forced, reversed, frame) forwards `animation.play(currentAnim, reversed, frame)`, omitting forced and sending an Int into Flixel's Bool argument. The adapter implements the declared public signature with all four arguments in their proper positions. This is a documented correction, not a claim of equivalence to that malformed body. Reverse start frames retain Flixel's index-from-end convention. The adapter deliberately does not use the newer loadFromSheet helper because that helper can disable one-frame sprites and resolves through a rebound provider, which differs from this constructor.

## Remaining gaps and next contract

The source stage is still incomplete: onLoad stops at foreground; onCreatePost stops at FlxAnimate; video play then fails because video creation was not reached. The older ColorSwap class and some legacy core note-skin defaults remain unresolved. Restored floor/structure visuals do not establish full stage parity.

The historical Stage source owns a separate FlxTypedGroup foreground, binds it before onLoad and passes `[stage, foreground]` to that callback. Historical PlayState mounts background stage, GF/opponent/player groups, then foreground. The current modern NV Stage is a container that owns the characters. Implement the older grouping and callback contract with explicit dialect/owner lifecycle handling; the existing HUD digit-layout capability check is not proof of a Stage API version; do not merely alias foreground to a modern stage or duplicate drawing/cleanup ownership. Then verify the legacy flxanimate.FlxAnimate and PsychVideoSprite constructors against the applicable library revisions. Keep older ColorSwap uniforms/outline semantics separate from the modern class until implemented.

Phase 2 and all menu, mod-management, dense Freeplay, category/favourite, sorting and performance goals remain open and retained.
