# Psych instance construction and placement

Local v0.0.23 development. The full-roadmap publication gate remains unchanged.

## Source and implementation

Pinned Psych revision `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`: ReflectionFunctions createInstance and addInstance, with the existing instance-argument and target-state services.

SourceScriptInstances preserves name normalization, null/non-array argument normalization, duplicate and missing-class diagnostics, parse-before-construction order, null-constructor results and exception propagation. Creation checks the current registry before construction and reselects the live active-state registry when publishing the object. It delegates actual construction to SourceNativeClassScope, retaining existing native classes and owner-scoped constructors.

Instance mounting follows source active-registry lookup, PlayState/game-over/front target selection, repeated live PlayState reads and captured insertion receiver/member-array order. It no longer applies an unrelated FlxBasic prefilter. SourceScriptSpriteLifecycle shares game-over insertion with the instance service; PsychSceneAnchors shares the existing character-group/flat-actor anchor policy between sprite and instance placement. Historical reflection constructors retain their previous adapter.

No chart/mod-specific production conditions or donor changes were introduced.

## Differential coverage

The exact pinned constructor and insertion callbacks are compared across 360 ordered cases, including duplicate/null entries, normalized/empty/null names, valid and unknown classes, optional and invalid argument arrays, registry changes during resolution/parsing/construction, null/throwing constructors, active/game-over/absent PlayState roots, missing tags and state changes during anchor evaluation. Comparisons include ordered boundary calls, warnings, return/failure outcomes, both registries and scene membership. Exception strings are not claimed as equivalent.

The comparison caught dynamic getter access for scene members and a null-PlayState failure-point mismatch. Shared native reads now preserve those contracts. The eval oracle models construction and target selection boundaries; separate compiled probes check real Flixel constructors and public registration.

## Limits and next work

Native source-class coverage remains bounded by the existing scoped class resolver; exact class-name alias/unknown-case behavior and all constructors are not established. The character anchor service retains the engine's flat-actor fallback and current imported stage metadata. This is not proof of donor StageData reload behavior or complete grouped-scene fidelity.

Next audit remaining Psych sprite/text/object helpers for active MusicBeatState registry selection versus captured host ownership, and source PlayState/game-over/custom-substate scene providers. Constructor publication is now separate from that remaining provider work. Full transitions, teardown, diagnostics beyond the covered calls, authored scenes and all earlier API/compatibility requirements stay open. Preserve every imported-menu, library/Freeplay, category/favorite, icon/star, independent sorting and fidelity-preserving performance goal.
