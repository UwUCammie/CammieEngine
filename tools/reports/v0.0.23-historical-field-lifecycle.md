# Historical NV atlas defaults and field generation

Development v0.0.23, 9 October 2026. Shared engine compatibility work; no donor or chart edits.

## Source evidence

Historical Nightmare Vision revision `7f96eb3b5a60352413229bf134bd348b79ad5fe6`:

- `source/gameObjects/Note.hx`, `StrumNote.hx`, `NoteSplash.hx` and `source/meta/states/PlayState.hx` default to flat `NOTE_assets` and `noteSplashes` asset names. The selected retained core contains those atlases in `shared/images`.
- `PlayState.startCountdown` constructs two default fields, captures player/opponent references, sets opponent visibility, calls one zero-argument `preReceptorGeneration`, generates opponent then player, fades player then opponent, and adds opponent then player to the display collection.
- `postReceptorGeneration` receives the skip flag. After it returns, modifier receptors are assigned in player/opponent order, then `preModifierRegister`, default registration and `postModifierRegister` run.
- The source generates fields after countdown approval, not before chart note generation. Modern NV instead has a per-lane pre hook and a configurable eager generation path.

## Implementation

`NightmareVisionNoteSkinDefaults.resolveOwnerData` now supplies all three omitted flat texture defaults for the existing verified legacy core layout. Null-only filling preserves explicit empty/custom paths and does not change the owner-independent modern static helper. Existing owner/core resolution supplies the actual atlas; there is no fuzzy search or borrowed sibling art.

The existing authenticated historical API selection chooses the old two-field generation path and deferred default. Both dialects use shared field factories, receptor generation, fading, display attachment, modifier services and owner assets. Historical hooks observe both empty live fields before generation, can replace the pointers or change field properties, and receive the authored skip flag afterward. Opponent visibility preferences are applied before the pre hook. Source stop/halt return values do not cancel generation. The modern per-lane path stays intact.

Historical display collection order is opponent/player. Modifier slots remain player/opponent by captured references, independent of display order and mutable IDs. Publication stays deferred through the historical post hook, including collection changes inside that hook. Exceptions release the publication guard.

Library lookup now uses `SourceLibraryPaths` for the shared base/Psych-era level, shared, then preload ordering. Historical NV starts with the shared level and resolves exact IDs through its selected owner's authenticated core catalog. Definitive catalog misses never borrow sibling or host files. Unindexed older cores retain exact scoped physical lookup. Modern flat-core selection remains unchanged. Explicit preload aliases and forced current-level namespaces have distinct regression coverage. Invalid library namespace separators are rejected before lookup.

## Remaining work

This package does not certify all historical field geometry. The older source uses different base-coordinate formulas, middle-scroll receptor offsets and a vertical entrance tween; these remain separate renderer/layout contracts. Historical constructor overloads and the supplied revision's inconsistent positional player-controls argument need source/version evidence before claiming exact factory parity. The shared modifier catalog remains under the broader Phase 2 API inventory.

The previous opening-video/song-clock discrepancy remains open until equivalent-load native checks distinguish decoder startup variability from a repeatable clock or scheduling error. Complete chart acceptance, advanced Animate, embedded/custom asset libraries and the remaining Psych/NV surface are still unfinished. All later menu, library management, categories/favorites, dense Freeplay, icon/star, independent sorting and performance goals remain unchanged.
