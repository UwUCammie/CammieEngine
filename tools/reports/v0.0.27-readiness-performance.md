# v0.0.27 importer readiness performance checkpoint

11 October 2026. Shared engine/importer code only. No chart/mod edits or publication.

## Workload and scope

The accepted independent-package refresh recorded 25 packages, 35 owners and 263 songs. This checkpoint reuses 39 distinct recorded readiness phases, including inspection, pending work, handoff and completion. The largest observed pending-output set contains 16,787 paths. No imports are forced merely to repeat the previously accepted file/receipt gate.

Native Windows console fixtures compile the production readiness classes and released reference sources. They replay the same owner, pending-output and song-folder inputs, checking every decision against both the reference and recorded result: 10,257 decisions. This isolates CPU readiness work from directory discovery, conversion, disk I/O, renderer work and diagnostic serialization. Full-library sweeps are not the normal cost of every Freeplay frame: the menu caches decisions by revision and updates visible rows.

## Existing v0.0.26 index

The initial real-data replay confirms the earlier index fixes a costly diagnostic path. At the peak pending-output set, a 263-song sweep took 1,511.6-1,516.6 ms with the v0.0.25 linear path scan and 5.44-6.06 ms with the v0.0.26 index. Building the index took about 41 ms. This explains why the old exhaustive diagnostic can produce a roughly 1.5-second gap; it does not prove all historical user-facing stalls have the same cause, nor measure total import speed.

## Current change

Preserve insertion order while normalizing and deduplicating paths. If normalized unique paths are already ordered, retain them without sorting a map's unordered keys again. If trimming or platform case folding changes their order, retain the existing full-sort fallback. Avoid allocating replacement strings for paths that already use forward slashes. The index remains detached and immutable per revision; queries, owner locks and filesystem verification rules are unchanged.

Regression coverage compares overlap decisions for reversed inputs, case-folded and whitespace-reordered paths, duplicate paths, exact/descendant/sibling boundaries, Unicode, null input and revision isolation. The test harness now actually exercises both Windows and case-sensitive normalization; its prior Windows host command added the Windows define to both iterations.

## Final matched measurement

After the build and test suite finished, a second standalone native fixture compared the v0.0.26 indexed implementation with the final candidate. Runs alternated reference/candidate/candidate/reference. Each measurement averaged 100 constructions or 100 full-library query sweeps; file parsing and decision-equality assertions were outside the timed sections. There was no concurrent build/test/import work during these timings.

| Pending paths | Reference construction ms | Candidate construction ms | Reference 263-song query ms | Candidate 263-song query ms |
|---|---|---|---|---|
| 12,865 | 48.159 / 42.891 | 23.736 / 21.514 | 3.485 / 3.812 | 3.349 / 3.111 |
| 16,787 | 58.397 / 53.488 | 27.925 / 24.105 | 7.632 / 7.875 | 5.926 / 5.932 |

The peak construction mean is 53.5% lower. Construction still exceeds one 60 FPS frame in this standalone workload; this is not a claim that all refresh/menu hitches are solved. The previously introduced v0.0.26 index provides the much larger query improvement over the v0.0.25 linear scan; do not attribute that earlier improvement to v0.0.27.
