# Retained-source buffer allocation checkpoint

Local v0.0.24 development. Shared importer paths only; authored chart/mod files and the playing installation are unchanged.

## Change

Snapshot capture, retained verification and transactional file hashing allocate at most the file's length or the configured chunk size, whichever is smaller. Empty files use one byte. Files at or above the chunk limit keep the existing chunk size, read count, progress/cancellation checkpoints and SHA-256 behavior. No checks, sources or assets are omitted, and no new metadata-trust shortcut is introduced.

## Real retained-library measurements

The installed library supplied 12 receipt-backed snapshots containing 16,593 files and 7,962,537,304 bytes. Verification used its production read-only API. Each run verified the complete tree and every file's content; receipt hashes were checked before and after. The source install was never used as a conversion/publication destination.

Based on actual file lengths, cumulative I/O buffer allocations per pass fall from 1,087,438,848 bytes to 463,574,872 bytes, a 57.4% reduction. This is total allocation traffic, not peak RAM. Each file remains independently buffered; no mutable buffer is shared between threads.

Two immutable native binaries, both already using Windows native SHA-256, were measured in baseline/candidate/candidate/baseline/baseline/candidate order to reduce cache and ordering bias. Baseline totals were 2.924, 2.863 and 2.848 seconds. Candidate totals were 3.410, 2.837 and 2.845 seconds. Medians were 2.863 versus 2.845 seconds. The small timing difference and one slower candidate pass do not justify a substantial speedup claim. The allocation reduction is the verified benefit. Warm-cache source verification is only one refresh phase, not an end-to-end 20+ mod refresh measurement.

Evidence: `tmp/v24-real-source-inventory.json`, `tmp/v24-sized-buffer-measurements.json`, `tmp/v24-sized-buffer-summary.json` and immutable fixture hashes recorded there. No unrelated build, regression suite or gameplay measurement ran during the alternating benchmark.

## Validation

The focused snapshot module passed 18 tests with two environment skips. Added boundary cases cover zero/one-byte files, SHA/block/chunk boundaries, threaded capture and verification, streamed file hashing with two chunk sizes and same-size tamper rejection. Native verification passed for all 16,593 files in all six measured runs. The canonical Windows build passed. The full suite ran 2,750 tests across 924 modules in 346.7 seconds, with 344 platform/donor skips. Windows initially blocked one generated path-patch fixture with Application Control error 4551; the same unchanged module passed all three tests on isolated rerun, without changing security settings. No other module failed. Logs: `tmp/v24-sized-buffer-build.log`, `tmp/v24-sized-buffer-suite.log`, `tmp/v24-sized-buffer-path-retest.log`.
