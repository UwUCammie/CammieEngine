# v0.0.27 library source-move checkpoint

## Reproduction and change

A generated Psych package with an authored name (no strong ID), two named
difficulties and one song was imported through the actual scanner, retained
snapshot manager and converter. Importing identical bytes under a different
source-folder name produced a second namespace and owner-qualified chart folder.
The native baseline failed with `Reimport changed chart identity after source move`.
Baseline log: `tmp/v27-library-lifecycle-baseline.log`; isolated install:
`C:/t/cammie-av-5ec3577d`.

The existing path-independent resolver was called before fingerprint preparation.
The scanner now prepares identity before destination planning and carries detached
chart/audio path inputs to the import worker. The worker rehashes current source
files before owner reservations and capture, instead of trusting hashes from the
UI scan. Per-thread scopes restore caller state on success and exceptions, and
keep nested scans and conversions separate from live menu identity reads.
Already-bound retained roots skip the additional scan fingerprint pass; conversion
still writes its existing provenance fingerprint. No additional discovery walk is
introduced. No new identity algorithm, donor edit or chart-specific branch was added.
Generated output formats and compatibility revisions are unchanged: this corrects
manual owner selection without scheduling a whole-library automatic rebuild.

## Native acceptance

Final executable SHA256: `e7485348e1a6daf5f1041e3cae3e010005c9dc76bad8223cda456f009fcea487`.

The opt-in `RuntimeLibraryLifecycleProbe` runs the real scanner, retained import,
converter and runtime handoff in fresh generated installations. Each run:

1. Imports the package and saves a favorite, category membership and named Hard
   preference through the real isolated host library save.
2. Imports an identical extraction at a differently named source path and checks
   identical published folder, owner and chart key plus saved metadata.
3. Re-imports that same source again and repeats the identity/metadata checks.
4. Imports distinct chart contents under the same authored package title and song
   folder. Its qualified destination and owner stay separate and it inherits none
   of the original favorite/category metadata.

Configured 60 and unlimited FPS runs both emit `library_lifecycle_verified` and
`success`. Each final Imported registry has exactly two distinct rows, one for
each actual package, without a third row for the moved extraction. All game
windows were muted on private, never-activated Windows desktops, with isolated
saves. The playing install was untouched. Logs:
`tmp/v27-library-lifecycle-final60.log` and
`tmp/v27-library-lifecycle-finaluncapped.log`.
Fixture paths, events, registry rows and matching native hashes:
`tmp/v27-library-lifecycle-proof.json`.

## Regression validation

Final Windows build passed (`tmp/v27-library-lifecycle-final-build.log`). All 58
related scan/ownership checks passed, with one existing skip
(`tmp/v27-library-lifecycle-related-final.log`). Compiled identity tests cover
detached fingerprint inputs, source-byte changes between scan and import,
per-thread hint isolation and restoration after a nested failed scope.

The canonical build/full suite ran 2,806 tests across 947 modules in 712.0 seconds,
with 344 skips and one failure: the receiptless rollback scheduler fixture did
not finish within its three-second resume deadline. The complete 20-test
transaction module passed on separate retry in 105.932 seconds, with one existing
skip. Its thresholds were unchanged. This broad run is not reported as clean.
Logs: `tmp/v27-library-lifecycle-suite.log` and
`tmp/v27-library-lifecycle-transaction-retry.log`. The final bound-root adjustment
was then rebuilt and covered by the related checks and both final native runs.
Keep parallel-suite scheduling stability visible as tooling follow-up.
Scoped whitespace and engine-owned punctuation checks passed.

## Limits and next gates

This proves source-path independence for an unchanged, uniquely matched authored
package while its installed ownership receipt still exists. It does not prove
uninstall/reinstall identity recovery, aggregate-root reshaping, explicit
user-named package moves, fresh-process difficulty UI, physical controller review
or ambiguous-owner migration. Those remain open. No throughput gain is claimed;
manual move recognition requires bounded chart hashing and audio filename/size
metadata, with no large audio decoding. No release was published.
