# Historical NV public visual distance

Local v0.0.23 development, 9 October 2026.

The historical source revision `7f96eb3b5a60352413229bf134bd348b79ad5fe6` gives ModManager.getVisPos a speed argument but explicitly passes 1 to getBaseVisPosD. The base helper itself still multiplies by the supplied speed. The adapter previously applied speed in both methods.

The owner render context now selects historical getVisPos semantics. Both public methods reuse the shared modifier transform's visual-distance equation. The built-in alpha modifier uses the same profile-aware equation as script-facing getVisPos, so historical fading is independent of the passed speed. Modern and standalone managers keep their prior speed-sensitive behavior. There is no mod/chart condition or new parallel modifier implementation.

A regression executes both pinned donor methods beside the production manager for past, future and equal timestamps with negative, zero, fractional and positive speeds. It also checks defaults, script-facing calls, modern/standalone owners and context changes without global profile leakage. Shared-renderer fade checks cover three speeds on the historical profile and speed-dependent modern fade boundaries.

This change covers the public helper contract and alpha distance sampling. It does not certify the full historical alpha modifier (including player selection and all submodifiers), visual-position/scroll-velocity transport, or sustain generation, clipping and orientation. Those remain in the Phase 2 source audit.
