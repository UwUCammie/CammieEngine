# Historical NV note-script ownership

Local v0.0.23 checkpoint; no push or publication.

## Source and shared implementation

Compared with Nightmare Vision `7f96eb3b5a60352413229bf134bd348b79ad5fe6`, `source/gameObjects/Note.hx` and historical PlayState's note-type registration.

Historical notes retain a writable `noteScript` reference selected when their type is assigned. Changing a registry entry does not change an existing note's attachment. Assigning the same type explicitly clears that reference, and built-in types clear it before their own reload. Update, reload and animation hooks read the attachment at their point of invocation, so a pre-reload hook may replace the script used by later hooks.

The shared note runtime now selects this behavior for historical NV. It uses the existing owner-scoped loader and interpreter, without cloning modules or creating another script execution engine. The historical `notetypeScripts` Map and modern ScriptGroup reference the same loaded module objects. Bare, instance and reflected map access use native typed state storage. Source map replacement is respected by subsequent type assignments. Each note owns its reference, not the script lifetime; reset/release clears the pointer and final module destruction remains with the shared groups.

Modern NV retains its live name-based registry lookup. Base and Psych note paths do not opt into historical attachment behavior. No chart/mod-name branch or donor edit was added.

## Limits and next work

This implements historical HScript attachment ownership. Historical Lua `noteScript` handles, editor-owned note registries and the old/new type value visible during nested setter callbacks remain unverified or incomplete. The production note setter currently exposes its new authored type before setup; the historical source stores it afterward. The pinned comparison here establishes attachment and callback ownership, not full setter side-effect ordering.

Default good/opponent handler identity, global/local hit notification order and arguments, exclusion of type/event scripts from global callbacks, absence of modern Pre/type-hit hooks, return/cancellation semantics, distinct hit flags, singer/ghost gates, scoring completion and wider-key input still need their connected source comparison. No full historical gameplay or roadmap completion is claimed.
