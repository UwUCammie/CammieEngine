## Source contract and implementation

Historical NV source at revision `54c53faa9493b1de88051fda7fcb7ff69e4f3950`, `source/meta/data/scripts/FunkinHScript.hx`, installs `addHaxeLibrary(libName, libPackage = '')`. It resolves the exact qualified class and replaces the short script global, including an unresolved null result. Resolution failures do not abort script loading.

`NightmareVisionScriptModule` installs that callback before source execution. `NightmareVisionScriptInterp.resolveSourceImport` shares owner-first class lookup with normal language imports and the Psych Iris bridge. Exact-class lookup uses the same native `Type.resolveClass` contract; language imports retain Iris's enum/module fallback. A seeded short name cannot substitute for another qualified NV class. Missing classes are diagnosed with script, phase and qualified name. Destroying a module clears its interpreter, and a previously captured helper cannot repopulate it. Psych keeps its existing strict failure and seeded-library behavior.

Unblocking the module exposed a native crash: a failed stage loading callback left a camera null, and `onSpawnNotePost` assigned `[null]` to a note's cameras. The shared interpreter now validates camera arrays for FlxBasic assignments before applying them. Null still means use default cameras, and empty/valid arrays remain valid; null entries produce a source diagnostic and leave the prior property intact. This guard covers assignments through the shared interpreter, not arbitrary later mutation of an already assigned array.

No donor/chart edits or name-specific production branches were added.

## Remaining gaps and next work

The legacy example still has no correct scenery. Successful smoke completion proves crash prevention and script progress, not visual parity. Remaining diagnostics include unresolved `gameObjects.shader.ColorSwap`, absent music during direct-smoke `onLoad`, unsupported `showRating` on the game view, and downstream play/zoom accesses after initialization fails. The new camera diagnostic correctly identifies and rejects those resulting null camera assignments.

Compare source startup through normal menu entry against direct smoke entry before changing music or callback ordering. Historical source stops an existing music object before constructing the stage, so a direct-boot harness difference must be distinguished from an engine bug. Then audit older state fields, qualified class adapters, sprite-sheet/video constructors and camera insertion against the relevant source revision. Avoid blind class-name aliases or silently substituting missing graphics.

The roadmap's complete build-context/external-library/reflection and gameplay gates remain open. Imported title/main/freeplay flows, mod management, categories/favourites, the dense Freeplay redesign, independent group/chart sorting and quality-preserving performance work retain their original requirements.
