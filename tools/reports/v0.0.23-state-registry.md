# Shared native state variable registry

Local v0.0.23 development. Publication remains gated on the full roadmap.

## Implementation and source contract

Pinned Psych revision `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`, `source/backend/MusicBeatState.hx`, supplies a per-state variables map and static getState/getVariables methods. The shared native MusicBeatState now owns that storage. PlayState.psychScriptVariables is a writable alias to the same map, preserving existing host callbacks without a second registry. Replacing either alias immediately changes the other view.

Psych source class registration exposes actual MusicBeatState and PlayState classes under backend.MusicBeatState and states.PlayState. HScript imports and Lua class reflection reuse one registration helper and retain native class identity. The static accessors read the active state on every call, including calls through a cached function. No captured-state facade, chart branch or mod-specific override was introduced.

## Verification scope

The source differential test compares 80 active-state cases, including two distinct states, null and an incompatible state. It also checks map replacement, per-state isolation, cached accessors, native class identity and interpreter-local imports. The existing reflection and HScript preset fixtures isolate unrelated dependencies; the new connected test compiles the real registration helper.

The native probe exercises Iris imports, Lua class reflection and writable aliases. It temporarily changes the active-state pointer to an unmounted MusicBeatState and restores it synchronously, without running a transition or frame on that state. This verifies accessor selection, not complete menu/state-transition behavior. It restores the gameplay registry and leaves authored gameplay untouched.

## Remaining requirements

Existing getVar/setVar/removeVar callbacks and object helpers still reference their owning PlayState. A retained callback invoked after a real state change needs a separate source-profile audit; modern Psych active-state semantics must not leak into historical NV ownership. Complete state creation/destruction, menu context, native source construction, lookup precedence, global-provider diagnostics and authored-scene acceptance remain open. All other compatibility/API, imported-menu, library, Freeplay, sorting and fidelity-preserving performance requirements remain unchanged.
