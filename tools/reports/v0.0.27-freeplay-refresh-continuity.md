# v0.0.27 live Freeplay refresh continuity

Date: 12 October 2026. Shared host-menu change; no donor/chart edits.

## Behavior

An import publication previously recreated Freeplay with a saved row number and
an empty search. Inserted or reordered rows could silently select another song.
The open menu now transfers a single-use bookmark containing its retained chart
identity, search, canonical difficulty name and view scope. The next menu finds
that identity in its fresh registry instead of reusing the old row index.

Difficulty restoration uses the existing LibraryDifficultyPreference resolver
and current chart availability. Provisional rows retain their owner/source key
without becoming playable. Missing, duplicate or filtered selections get a
visible notice rather than silently inheriting the previous difficulty. The
bookmark does not write library metadata, change ownership, unlock imports or
persist across unrelated menu launches. Imported scripted callers survive this
same-menu replacement; the existing zero-argument state factory remains valid.

## Limits and next work

This establishes continuity when publication rebuilds an open Freeplay menu,
including publication after returning from gameplay while a worker is held.
The initial checkpoint did not establish continuity after that menu was
already destroyed; the session extension below covers this. Complete
move/reinstall and ambiguous-owner migration remain open.
The real worker fixture exercises coordinator publication with a small generated
conversion payload; it does not replace full donor-import acceptance. Existing
25-package refresh correctness evidence remains separate and was not rerun.

Next finish library lifecycle acceptance, then broader viewport/long-label and
controller review, safe uninstall and authored imported-menu sessions. Preserve
all original Phase 0-7 goals. These native runs are functional checks, with
background import work, not latency or throughput benchmarks. No publication.

## Session-return extension, 12 October 2026

The view scope is captured on that instance, before static category/owner fields
can be changed by another destination. On the next Freeplay entry, a matching
view with a different import generation reuses the existing identity/search/
difficulty restoration path. Unchanged registries retain ordinary entry behavior;
different views discard the bookmark, including empty categories that redirect.
It is consumed once, does not persist to disk, and cannot recreate an imported
scripted caller. Capture failure discards the stale bookmark and permits teardown.
