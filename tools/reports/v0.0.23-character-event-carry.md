# Character event animation carry checkpoint

Local development v0.0.23. Publication remains gated on the complete roadmap.

## Source and shared implementation

Compared `Change Character` in historical Nightmare Vision revision `7f96eb3b5a60352413229bf134bd348b79ad5fe6`, `source/meta/states/PlayState.hx`, and modern NV revision `733165c42ca71eb0961a70e4173b2d81ba4a29ea`, `source/funkin/states/PlayState.hx`.

Both dialects retain one native event implementation and Psych's shared role parser. The event now samples the live role after publication callbacks, rather than carrying an animation to the cached return value when a callback changed the actor again. Out-of-range role selectors use BF for the event's animation sampling, as in both sources. This does not yet correct historical out-of-range publication semantics.

Historical carry checks whether the replacement contains the requested animation. It can start that animation when the replacement has no current animation; a missing alias leaves the replacement's current animation and frame alone. Modern NV retains its distinct current-animation gate, including a null-controller guard. Historical preload admission preserves source null-string failure while retaining the shared, distinct numeric preload aliases. Ordinary host/Psych character replacement paths are unchanged.

No production mod/chart names or donor changes were added. Construction, playback and publication still reuse existing engine services.

## Remaining ownership work

This checkpoint fixes the event wrapper, not the complete historical replacement transaction. Pinned source audit found the following necessary follow-up:

- Independent writable boyfriendMap/dadMap/gfMap caches belong to PlayState. Historical preload keys use the requested ID, and its order is construct, map insert, group add, position, hidden alpha, then character script loading. Do not silently use modern CharacterGroup.map semantics.
- Historical changeCharacter captures old identity/focus before loading, rereads live actor/map after callbacks, migrates playfield owners by identity, updates GF visibility and role icons, then publishes Lua names and script role/group/ghost references in source order. Preserve same-name and invalid-role behavior and final health-bar refresh callbacks.
- Wire historical preload/public methods and initial-role map seeding through shared constructors, actor membership, icons, bars and script services. Audit placeholder GF exposure, focus consumption, ghost publication, constructor/script failure, reentrant loading and teardown before claiming full parity.
- Keep modern CharacterGroup behavior distinct where the pinned sources disagree. Test each dialect and native integration rather than replacing the modern group implementation with the historical state algorithm.

Later property/scroll-speed builtins, wider Lua coverage, lifecycle and authored scenes remain open. All imported-menu, library/freeplay and fidelity-preserving performance goals are retained. Nothing is authorized for release by this checkpoint.
