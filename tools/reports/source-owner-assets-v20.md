# Source owner Assets facades, v20

The shared Lime and OpenFL facades now take an explicit `SourceOwnerAssetContext`. The existing Psych constructors keep their package-scoped owner behavior. Nightmare Vision can select one authenticated `package` or `core` scope, or the raw compiled `Assets` composite, which checks package before core and never falls through to host or loose owner files.

The composite Lime `getLibrary` surface is a real `lime.utils.AssetLibrary` subtype. The OpenFL surface is a real `openfl.utils.AssetLibrary` wrapper over that same Lime view. Typed reads, lists, and asynchronous loads use the common owner facade and its composite proof guard. The context owns stable Lime and OpenFL cache objects, including the public cache API and its enabled flag. Cache entries are cleared when either selected scope's committed proof changes. Completion callbacks verify both scope proofs and the currently winning package/core identity before publishing a cache entry.

Owner-local Lime and OpenFL event providers are shared by each owner, engine, and context scope. Loaded libraries forward their change events to those providers and direct library listeners. Identity retirement detaches library listeners, releases composite caches and event providers, and leaves other owners untouched. A retained composite library refuses stale reads or loads, and its stale `unload` does not unload a newer package or core identity.

Forced-eval validation passed 7 focused tests across the context, Psych facade, owner library lifecycle, Nightmare Vision binding, and event-provider modules. The focused cases cover real Lime/OpenFL library class identity, wrapper linkage, owner-local event dispatch and teardown, composite listener removal, cache lifecycle, and release after the owner directory has already been removed. Root's integrated Windows receipt-bound package/core fixture passed real import publication, image pixels, library Futures, public cache isolation and clearing, event forwarding and owner teardown. Evidence: `tmp/v20-nv-assets-native-9.log`; the release checkpoint records the final executable's acceptance receipt.

The file-backed library loader still diagnoses unsupported custom handlers and incomplete load metadata rather than claiming their behavior. Startup registration of embedded manifest libraries and dynamic library registration remain outside this package. The ordinary typed getter path can serve verified physical entries whose library load profile is unavailable, while explicit library loading requires a complete supported load profile.
