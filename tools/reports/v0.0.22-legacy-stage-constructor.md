# Legacy Nightmare Vision Stage constructor checkpoint

## Source and scope

Compared `source/gameObjects/Stage.hx` at Nightmare Vision revision `54c53faa9493b1de88051fda7fcb7ff69e4f3950` with the current modern `funkin.objects.Stage` adapter. Historical Stage is a FlxTypedGroup, with a separate foreground group. Modern Stage is a FlxTypedContainer that owns character groups. They cannot be aliases without changing ownership, traversal and destruction.

`gameObjects.Stage` now resolves to `NightmareVisionLegacyStage` through the existing interpreter class and constructor bindings. The ordinary Stage preset and `funkin.objects.Stage` remain modern. The adapter reuses captured Stage owner services, Paths, interpreter modules, native Flixel groups, stage path validation and template fields.

The implemented HScript constructor contract includes mutable stageData, spriteMap, stageScripts/hscriptArray, separate foreground, script registration before callbacks, `add`/`stage`/`foreground` bindings, and `onLoad(stage, foreground)`. Stage teardown releases scripts without an extra onDestroy callback and destroys background members. Foreground is separately owned by the caller's scene and is not destroyed by Stage.

Legacy lookup reads only `stages/<name>.json` using strict JSON and verified owner/core lookup. Script extension order is hx, hscript, hxs, lua, with owner-before-core resolution within each extension. Lua selection is explicitly diagnosed as unsupported rather than passed to HScript. Full legacy Lua Stage construction is still open.
