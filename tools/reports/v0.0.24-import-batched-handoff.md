# Bounded import completion handoff

Local v0.0.24, 10 October 2026. Shared engine/importer changes only; no chart, donor or mod-specific changes.

## Implementation

ImportRefreshManager now rebuilds difficulty support for at most four songs per safe-menu poll. A queue-wide four-millisecond soft deadline is checked between batches, not during a filesystem operation. This is not a hard frame-time guarantee. The existing ModuleFunctions main-thread completion function still handles cache invalidation and difficulty discovery; no mutable visual/cache work moves to the worker thread.

The reservation stays held across batches. Its cursor advances only after successful completion of the batch. Gameplay defers further work, an error retries the unfinished batch, and repeated manual-import UI polls cannot replace a partially applied song list. The generation change, completion status and readiness release occur only after the entire package finishes. Unrelated ready packages remain playable. Cursor state is discarded on reservation release or a newly queued handoff.

## Native refresh evidence

A muted, never-activated private desktop ran the same retained 242-song, 23-root aggregate package at 60 FPS. No builds, tests or independent hashing overlapped the timed run. Production source and binaries were restored before launch; diagnostic revision 12 only advanced the private fixture's prior revision-11 receipts through normal refresh.

| Measurement | Prior discovery-reuse run | Batched handoff run |
|---|---:|---:|
| Launch to completion | 361.454 s | 364.493 s |
| Reported refresh elapsed clock | 359.869 s | 362.888 s |
| Maximum update/draw cost over the run | 346 ms | 171 ms |
| Completion interval maximum update/draw cost | 346 ms | 146 ms |
| Maximum start-to-start frame gap | 280 ms | 268 ms |

The handoff completed in 61 ordered batches, covering every song exactly once. Cumulative time inside the shared completion function was 357 ms; the slowest batch took 8 ms. The last reporting interval contains 31 rendered frames with median frame spacing of 17 ms and a 95th percentile of 19 ms. The harness polls from both Freeplay and its observer, so there can be two batches in one frame. The terminal frame still has no following frame-gap sample.

This improves completion responsiveness, not conversion throughput. Total time differs by about three seconds (0.84%) in successive single-machine runs; no total-speed improvement is claimed. A separate completion cost remains at 146 ms, and background phases still have occasional hitches. Freeplay currently reconstructs its state on an import generation change; that is a candidate for profiling, not yet a proven attribution of the remaining cost.

## Fidelity and difficulty checks

All 24,702 output hashes and the commit receipt passed independent verification. Of those files, 24,609 are byte-identical to the preceding output. The remaining 93 generated JSON files have equal contents under exact decimal, boolean, array-order and string/null comparison; only object-key order/formatting differs. Pre-run JSON bytes were archived and checked against their manifest hashes.

The first difficulty comparison rejected differences in dynamic integer IDs against an earlier standalone probe. That probe discovered songs in sorted order from raw definitions, whereas actual menu startup discovers them in registry order. A second native diagnostic restored identical initial difficulty definitions and support maps before running the original all-at-once and new batched paths. Every support array for all 242 songs matched exactly, including order. Those arrays also matched the integrated refresh. Reproducing the historical sorted probe matched its old integer IDs and confirmed identical difficulty names to the current result. The verifier preserves this distinction rather than ignoring index differences without evidence.
