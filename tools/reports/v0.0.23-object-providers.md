# Psych sprite and text state providers

Local v0.0.23 development. The full-roadmap publication gate remains unchanged.

## Source and implementation

Pinned Psych revision `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`: sprite constructors/add/remove/type-existence callbacks, Animate replacement, TextFunctions construction/lookup/add/remove, LuaUtils object/target helpers, and CustomSubstate instance publication.

PsychObjectProviders shares live native PlayState/game-over/base-state target selection with public reflection. Modern sprite, Animate and text callbacks use MusicBeatState.getVariables instead of the script host's captured map. Sprite removal uses the raw direct-object rule; text property callbacks use the source nested path rule through SourcePsychReflection and the existing shared raw traversal. Type-existence checks consult the active registry. Imported assets, fonts and preference context remain scoped to the originating script/mod.

Text camera selection occurs after formatting and follows the current PlayState. With no PlayState, native default cameras remain intact; a present PlayState with a null HUD camera retains source forced-camera behavior. Animate replacement removes from the current PlayState. Sprite mounting uses the current source scene and shared character anchor.

PsychCustomSubstate publishes its native instance before create callbacks and clears it after destruction callbacks. Text removal selects that published instance, rather than an unrelated queued substate on the original host. Text and sprite removals retain their distinct transactions: text clears its previously captured registry after removal/destruction, while sprite removal reselects the live registry after scene removal.

Historical profile routing is preserved. No donor edits or chart/mod-specific production branches were added.

## Coverage and limits

The public reflection oracle now includes the exact pinned text-lookup expression: 1,136 ordered cases in total. Existing source-compared sprite/text lifecycle transactions still pass. The native custom-substate fixture now asserts publication during create/destroy callbacks and absence before queued creation and after destruction.

The compiled probe retains public callbacks while replacing native active-state and PlayState pointers. It checks constructors and type existence, nested text/global-bracket lookup, current HUD/default cameras, game-over add, published custom-substate removal, and the distinct captured-text/live-sprite registry behavior under removal listeners. These use disposable objects and unmounted scenes, not full user-driven transitions.

Remaining object helpers still need individual source audits: generic geometry, offsets, animation/asset operations, tagged properties and save helpers retain existing owner-aware paths. Finish CustomSubstate's public static/HScript facade, open/close/insert semantics, owner-versus-singleton callback routing, queued cancellation and parent teardown publication timing. The new published instance does not by itself establish full CustomSubstate parity. Preserve class/diagnostic breadth, full transitions, teardown, authored scenes and all previous compatibility/API and later menu/library/Freeplay/category/favorite/icon/star/sorting/performance goals.
