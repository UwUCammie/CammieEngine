# Historical event-map ownership and HScript initialization

Development v0.0.23, local only. Shared compatibility/loader changes, no chart/mod branches or donor edits.

## Contract and implementation

Pinned Nightmare Vision revision `7f96eb3b5a60352413229bf134bd348b79ad5fe6`, `source/meta/states/PlayState.hx`: eventScripts map, the HScript event-construction branch in getEvents, callOnScripts filtering/appending, and event-script selection.

Historical HScript event construction runs before map insertion. onLoad receives the event name and sees its map entry, while the new module has not yet joined the main/HScript arrays. Those arrays receive the same module after onLoad. An existing same-named global does not suppress event construction. Gameplay-seeded historical modules retain their authored names and bypass modern unique-name tracking; otherwise source name-based filtering could dispatch an event twice. Modern construction/uniqueness and its registry entries remain isolated.

The historical registry now owns the actual writable eventScripts map. Bare, instance, class and reflected map access share identity. Historical loader, event callback selection and special-script filtering read the current map, so replacement/removal and unplanned aliases affect subsequent calls. Replacing the map does not destroy its old modules or mutate retained references. onLoad can itself replace the map without the loader restoring its old entry afterward. Combined broadcasts append current map values exactly as before. Historical lookup is read-only; authored scripts are loaded explicitly during event preparation. Modern NV keeps typed event groups and their existing selection/loading behavior.

One shared NightmareVisionScriptHandle dispatch helper serves the live registry and event backend. Lua-compatible handles delegate to the existing scopes; no VM is duplicated. A former secondary Lua-event map has been removed so it cannot restore entries deleted from the source map.
