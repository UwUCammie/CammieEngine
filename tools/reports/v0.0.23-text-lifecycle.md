# Historical Lua text lifecycle

Local v0.0.23 development. The full-roadmap release gate remains in force.

## Source and shared implementation

Pinned source: historical Nightmare Vision `7f96eb3b5a60352413229bf134bd348b79ad5fe6`, `source/meta/data/scripts/FunkinLua.hx`, ModchartText, makeLuaText/addLuaText/removeLuaText, resetTextTag and getTextObject.

SourceModchartText subclasses the existing native FlxText rather than creating another renderer. It carries the script-visible wasAdded flag and applies the source 16-point owner-resolved vcr.ttf font, white centered text, black two-pixel outline, HUD camera and zero scroll factor.

SourceScriptTextLifecycle shares creation, replacement, mounting and removal transactions over the live registry and native scene operations. Creation strips dots from its tag before replacement. Replacement kills the prior object, removes it from the play state only when wasAdded is true, destroys it, then removes its tag. Mounting and ordinary removal use the current active scene, including game over. Non-destructive removal keeps the reusable registry entry. Destructive removal preserves kill, conditional removal, flag clearing, destruction and registry deletion order. Registry access stays live after callbacks. Text helpers resolve their own namespace before a literal play-state property, independently of sprite tags.

The Lua lifecycle wrappers are installed after general binding overlays. Source construction returns no object to Lua; the internal native helper retains its return value for engine callers. Other profiles keep their existing text construction path. There are no chart/mod-specific branches or donor edits.

This checkpoint does not certify the full text API. Native checks use an unmounted game-over object, not a real death transition. Full authored text rendering and arbitrary registry/scene teardown remain open.

Compare Psych/current NV text contracts and reuse these services wherever the source semantics match. All menu, library/category/favorite, dense Freeplay/icon/star, independent sorting and fidelity-preserving performance requirements remain intact. Do not publish until every roadmap gate is complete.

Native container distinction: the current Flixel destructor detaches an object from its owning container. Historical resetTextTag explicitly removes from PlayState before destruction even during game over; the shared transaction retains that order while the native destructor subsequently detaches the game-over member. A destroyed member therefore becomes an empty slot instead of remaining a destroyed reference. Native raw scene-array parity is not certified and remains part of the broader scene/lifetime audit. The native probe checks the actual destructor callback timing and does not attempt to keep an unsafe destroyed object mounted.

The first native lifecycle run rejected a probe assumption about destructor callback timing. FlxText clears textField before its superclass detaches the container, while FlxSprite clears animation afterward. The corrected probe observes that exact order. No production change was needed for this correction; the failed run remains in `tmp/v23-text-lifecycle-native60.log`.
