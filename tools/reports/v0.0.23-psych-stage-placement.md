# Shared Psych stage placement checkpoint

10 October 2026, local v0.0.23. No push, tag or release.

Selected compiled stages and their nested native/source helpers now share a scene placement phase. The phase captures the actual active scene when its class scope is bound, separately from the retained asset owner. Initial scenery goes before that scene's actors because this host creates actors before running imported stage construction. Additions to other scenes preserve ordinary append order. Returning to the original scene during construction retains its initial placement; createPost ends that phase for both retained helpers and helpers constructed later.

Independent source scopes default to ordinary insertion. The existing standalone adapter behavior remains available to detached callers. Rebinding the same construction service is idempotent; changing its class owner is rejected. All implementation changes are shared compatibility behavior, with no chart/mod branches or donor edits.

The source comparison uses the pinned Psych BaseStage constructor and its actual add implementation (revision 5c67ced49e5a98535298a6daa3f8f4ec79ac8399). Compiled source creates actors after stage construction; the real owner-class loader runs against a host whose actors already exist. Their resulting member orders must match. Cases cover nested source and direct native helpers, an asset owner different from the construction scene, switching scenes and returning during create, retained/new helpers after createPost, independent scopes and repeated binding. The initial fixture assumed a block-bodied public add method; extraction was corrected to use the donor's actual expression-bodied method.

Native checks use real FlxBasic objects in isolated scene lists and the real source class loader/runtime. They exercise initial native-helper placement, foreign-scene appending, return to the construction scene, retained helpers, callback-created helpers and owner cleanup. The gameplay capture is a harness health check, not visual acceptance of every authored stage. The disposable runtime has a v0.0.22 label asset; its executable is the v0.0.23 development build.

## Next work

Automatic owner-class imports in ordinary Psych HScript remain a separate integration task. SourceIrisBridge currently imports seeded/native types, while CodenameScriptClassLoader owns HScript-ex descriptors for selected source stages. Reuse that loader and owner scope rather than adding another parser/class registry. The integration needs incremental imports preserving class/static identity, Iris construction/get/set/call and reflection support for source class symbols/instances, native-versus-source lookup precedence, owner-isolation diagnostics and lifetime that retains stage callbacks until state teardown. Verify the same contracts through plain HScript and runHaxeCode, including repeated imports, two owners with the same class name, failed imports and disposal.

Keep invalid-state parity, reentrant/multi-scene rollback, group-view lifetime, default-GF consumption, countdown/end-song internals, dynamic source-method semantics, camera/static transitions and mounted source-menu acceptance open. All earlier API/fidelity requirements and all later menu, library, categories/favorites, Freeplay, icon/star, independent sorting and performance goals remain required. This checkpoint does not satisfy Phase 2 or the full-roadmap release gate.
