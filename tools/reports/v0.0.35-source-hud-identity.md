# v0.0.35 source HUD identity and song-title display

## Cause and shared fix

Swag Messiah's untouched `ballsNEvents.lua` moves the HUD out on song start and returns it at beat 16. Each target is calculated from `getProperty` of the current HUD position plus or minus 160. Psych's source PlayState creates the health bar at `FlxG.height * 0.89` for upscroll, which is 640.8 at a 720-pixel logical height.

The engine keeps native typed bar and icon fields for their original ownership and teardown while displaying the actual source HUD groups. `compatDoTween` resolves the live groups. The later modern Psych property binding replaced `getProperty` with `SourcePsychReflection` backed directly by the native class scope, bypassing those existing live HUD aliases. Reads continued to return native `healthBar.y = 652` and `iconP1.y = 565.8` after the visible source objects moved. The return tween therefore targeted `652 - 160 = 492`, matching the high health bar in the reported screenshot.

`PsychObjectProviders` now recognizes HUD aliases on the active PlayState or PlayState class and reuses the existing `compatReadPathPart` and `compatWritePathPart` boundary. Its direct/text helpers and modern `PsychPropertyBindings` share that boundary. Ordinary properties continue to use the native class scope. Bar backgrounds, time bars, source icons, class paths, replacement pointers and null pointers follow their existing alias rules. No song-name branch, baseline adjustment, donor change or chart edit was introduced.

## Native evidence

A fresh private runtime was extracted from the published v0.0.34 package and imported the immutable Shadow Wizard donor using the full native ImportWorkflow transaction. The import completed with two songs, 89 copied assets, zero errors and zero missing dependencies. Observer Lua was added only to the private runtime copies. Gameplay ran muted on a never-activated private Windows desktop with private saves, practice and botplay.

The before-fix native run reproduced the visible high bar. At song start the source bar was 640.8, then moved to 812, while Lua reads remained 652. After beat 16 the source bar was 492, the source icon was 405.8, and the native fields remained unchanged. The source background and fill children moved with the actual source group. Logs and framebuffer capture are retained under `tmp/v35-swag-fresh/tmp/v35-swag-fresh-before-fix-60.*`.

The final runner `tmp/v35-hidden-hud-fresh-play.py` captures at 11.5 seconds and exits after 14 seconds. It asserts the source Psych profile, matched Lua/source position samples, an actual out tween, restoration to the original 640.8 source baseline, icon restoration and agreement between the group and its background/fill children. The integration build passed this native probe with 13 matched samples: the actual source bar moved from 640.8 to 800.8 and returned to 640.8; the source icon returned to 565.8. Lua reads matched the visible source objects throughout, while the separate native bar field remained 652. The framebuffer confirms the restored bottom HUD and the `Swag Messiah` title. Final proof, binary hash and three matching original/retained donor-script hashes are recorded in `tmp/v35-swag-fresh/tmp/v35-hud-proof.json`.

The donor ratings script's separate `showRating` reflection error is present in the baseline evidence; it does not account for the health-bar displacement and was not changed in this patch.

## Display-only titles

Gameplay, story track lists, native/imported pause information, loading information and module song lists now call the shared `FreeplaySongTitle.display` helper. It replaces dashes with spaces and capitalizes the first character of each word. Storage IDs, chart names, audio paths and script globals retain authored identifiers. The existing source timer construction fixture now checks its rendered `Source Song` label using the real shared helper.
