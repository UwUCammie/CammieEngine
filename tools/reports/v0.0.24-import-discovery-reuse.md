# Verified retained discovery reuse

Local v0.0.24, 10 October 2026. Shared importer change; no chart/mod or donor edits.

## Implementation

Retained refreshes now retain one isolated discovery result within their active ImportIO transaction. The result is serialized before dependency scanning mutates destination planning, diagnostics or converted charts. Internal aliases and maps are preserved while the public scan cannot mutate the saved result. Storage is bounded; unsupported objects or excessive serialized size retain ordinary discovery.

The plan is accepted only after the manager's normal scan/root/diagnostic checks. Consumption requires the same source, selector, active transaction, retained root/engine restrictions, namespaces and labels, and no cancellation. The full source snapshot verifier runs again before consumption: receipt identity, exact tree, containment and every retained file hash remain checked. Changed sources abort the transaction. Results are consumed once, including verification failure, and discarded on scope teardown. Nested scopes cannot use a parent's result.

The import path still applies package names, recomputes source fingerprint hints, plans live destination collisions, validates ownership, supports cancellation, stages assets and publishes atomically. Winner source information is rebuilt in its original order, retaining independent same-named songs and skipped aliases. Direct imports keep live discovery unless called inside this accepted retained transaction. Nothing is persisted as a reusable discovery cache across sessions.

## Output equivalence and integrity

The initial strict byte check found 93 changed JSON files, so acceptance was withheld until an uncached reference was generated. Hash-matching prior copies were recovered for 57 files and their parsed contents matched. The following reference then regenerated every output using ordinary discovery, with the candidate's changed files archived before replacement.

Across all 24,702 output paths, 24,609 files are byte-identical to the uncached reference. All remaining 93 JSON files are semantically identical. The comparison ignores only formatting/object-key order: it preserves array order, distinguishes booleans from numbers, and compares exact decimal values rather than rounded Python floats. This includes converted V-Slice charts, note definitions and character registries. Both candidate and reference had every installed hash and transaction receipt independently verified after completion. Candidate owned bytes: 11,296,252,147. No source/chart behavior or media quality was reduced.

The diagnostic fixture advanced normally from revision 9 to 10 for the candidate and 11 for the reference. Production common revision 3 and its accepted source/executable/library were restored before launch and verified afterward. The reference diagnostic closes the discovery plan before take so it exercises the ordinary discovery branch. Its trace confirms two complete passes versus the candidate's one. The private fixture now carries diagnostic revision-11 receipts; do not alter them manually or confuse them with production receipts.
