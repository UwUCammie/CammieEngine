# Freeplay imported-menu discovery profile

Local v0.0.24, 10 October 2026. Evidence checkpoint; no new production optimization in this pass.

## Measurement

The production executable ran for 25 seconds against the separate 25-package installation on a muted, never-activated Windows desktop at 60 FPS. This enabled the existing `--smoke-pacing-only` section profiler, which the earlier aggregate refresh runs had not enabled. No build, test or independent hashing overlapped the measurement. Runtime completion succeeded, settings were restored, and the process exited.

Freeplay initialization recorded 868 ms total, including 821 ms creating the imported HXC menu runtime. That runtime spent 747 ms discovering script files and 74 ms reading song manifests; translation and execution recorded zero milliseconds at this timer resolution. Visible alphabet rows took 21 ms and menu chrome took 4 ms. These are initialization section durations, not GPU timings or steady-state frame costs. Ordinary settled frames were generally 0-1 ms update/draw; an icon-loading frame reached 44 ms. The previous refresh's residual 146 ms terminal cost is not attributed to this scan solely from this new measurement.

## Candidate and current gate

`HxcScriptDiscovery.collectRoot` reads every directory and asks `FileSystem.isDirectory` separately for each entry. A scratch prototype reuses Windows enumeration's file-type metadata while keeping the existing sorting, depth/file budget, family classification and full-path outputs. Reparse points use the existing live directory check; failures fall back to the ordinary filesystem implementation. Non-Windows targets retain the portable path. There is no song/mod-name condition or donor change.

The isolated native prototype compiled. Its executable was rejected before launch by Windows Application Control. The Code Integrity log confirms events 3077 and 3033 citing Enterprise signing-level requirements and policy `0283ac0f-fff1-49ae-ada1-8a933130cad6`. No security policy was changed. The prototype remains only under `tmp/v24-directory-probe`; neither the helper nor the traversal change has been integrated into production. No performance saving or output equivalence is claimed.

Before integration, require native original/candidate comparisons over the same roots in reversed order, exact discovery order and family arrays, and focused coverage for Unicode/long paths, empty/missing directories, file-like directory names, reparse points, limits and errors. Then verify the complete Freeplay initialization cost and rendering behavior, and run the integrated regression gate. This native execution restriction also leaves the separate 25-package forced-refresh acceptance check pending.
