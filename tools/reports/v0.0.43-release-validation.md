# v0.0.43 release validation

This user-authorized incremental alpha fixes the blank screen players were left on when they removed a mod while an import refresh was running. Remaining roadmap requirements stay open.

## Build and regression evidence

The final Windows build completed successfully. Its executable SHA-256 is `610f9067a0b51826ee59f35c1ac347ceeb7d5bab437a4fdaae7539def4d1ccd5`.

The full suite executed 3,485 tests across 1,201 modules in 645 seconds with 347 fixture/platform skips and zero failed modules, through `run.bat package`.

The first two gate attempts failed on timeouts while other applications loaded the machine, and once because a retried interpreter fixture reused the folders a hung attempt had left behind. Two threaded interpreter fixtures hang under that load and pass alone in about 2 seconds. The test runner now runs modules marked `RUN_ALONE = True` one at a time after the parallel pool, and those two fixtures are marked.

Before packaging, a whole-project type check passed and the focused tests for every changed file passed (530 tests across 117 modules).

## Native checks

Muted runs on a private, never activated desktop against a private copy of a real install:

- With a real startup import refresh forced, the removal screen opened during the refresh showed "Mod refresh in progress" with an explanation, progress and Return, then moved on to "Remove installed mod?" by itself with Keep first.
- With no refresh pending, the normal removal review appeared and Back returned to Freeplay.
- Back during the refresh wait showed "Returning to Freeplay..." and returned to Freeplay.
- No file changed in any of these runs (72,845 files hashed before and after).
- Isotope and Amusia each played 60 seconds on botplay with no frame over 300 ms and no errors.

Not verified natively: the scenario with a large Nightmare Vision refresh (a smaller refresh was used), the "Returning to Freeplay..." text after a normal review (it was logged on the refresh path), and a refresh that changes a package while its review is open (covered by unit tests).
