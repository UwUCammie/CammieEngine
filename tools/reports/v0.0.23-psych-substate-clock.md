# Psych inherited substate clock and shared sections

Local v0.0.23. The complete roadmap remains the publication gate.

## Implementation

The pinned Psych revision is `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`. Its MusicBeatSubstate has fractional step/beat fields, section advancement and rollback, source controls and a state elapsed-time rule that were missing from the native host base.

PsychMusicBeatSubstate now exposes that source behavior above the native MusicBeatSubstate child-update path. PsychCustomSubstate inherits it for source lifecycle use, while historical custom substates retain the existing host beat clock and controls. Psych and NV state/substate section traversal now shares SourceBeatSections; dialect-specific update and callback timing remains at the callers. NV service functions remain live reads.

Conductor now exposes the pinned inclusive BPM-segment selector, retaining live map entry identity. Generated BPM segments carry stepCrochet. Substates select the segment at raw song time before applying the live source noteOffset. Detached preference data and defaults now supply zero noteOffset. MusicBeatState exposes and maintains the shared elapsed counter, including reset after creation. Source controls reuse PsychControlsCompat rather than creating another input implementation.

Source class bindings and recognized imports expose backend.MusicBeatSubstate. Native testing found Iris's native-name-first construction selected the host MusicBeatSubstate despite the source import. The existing identity-based constructor factory now routes this source class consistently, preserving script-local class identity and avoiding a global interpreter precedence change.

## Limits and next work

This is source base-substate API coverage, not complete authored-menu acceptance. Arbitrary compiled subclass overrides, nested substates, reentrant parent teardown and malformed section metadata remain unverified. The source MusicBeatState gameplay/menu timing surface and remaining generic object providers/class diagnostics still require audit. Keep all previous compatibility/API requirements and imported menus, library management, Freeplay design, categories, favorites, icons, stars, independent sorting and fidelity-preserving performance goals open.
