# Shared Psych stage construction checkpoint

10 October 2026, local v0.0.23. No push, tag or release.

PsychStageConstruction now owns the shared registry insertion, source-super hooks, adapter attachment and post-create phase handling previously embedded in the selected compiled-stage runtime. The selected runtime retains its existing dispatch and teardown ownership. Direct source BaseStage construction registers the actual native instance before its superclass constructor and create callback. It uses the same live context as source stages, with ordinary scene insertion instead of the selected-stage actor-order adaptation.

Psych's Iris constructor factories and native reflection scopes register backend.BaseStage by class identity. The shared owner-class scope now also supports explicit native factories, with source descriptors retaining priority and no process-global registry fallback. Direct native BaseStage construction inside an owner-source method uses this factory and is retained by that stage runtime for cleanup. Classless source construction can use the same scope binding. Other engine classes retain their existing fallback constructors.

The pinned Psych reference is revision 5c67ced49e5a98535298a6daa3f8f4ec79ac8399. A standalone comparison compiles its actual constructor with a native subclass to check registration before create and constructor return. Actual-adapter checks cover direct factories, active-state changes, retained registration, normal scene order and binding the same service to an independent source scope. Existing nested-stage/failure/context tests remain in place.

During verification the isolated fixture initially used the wrong Haxe classpath precedence and pulled in the engine Main; its classpath was corrected. The broad suite also exposed a transient Windows cache-publication rename failure. The isolated cache rerun passed. The final publication rename now uses the cache's existing bounded Windows retry helper, with a sharing-lock injection test proving one build and two rename attempts. Permanent errors and quarantine safety retain their existing checks.

The first native run exposed unsafe inferred return types in the chained state/stage factories. Haxe generated MusicBeatState/BaseStage casts for unrelated constructor results, causing a native access violation. Both factory closures now declare Dynamic return types. A subsequent probe failure was its missing standard Type binding; that binding is now supplied in the isolated probe, as in normal gameplay. Generated C++ was inspected, and the native probe additionally constructs an unrelated FlxBasic through the chain to verify identity and lifetime.
