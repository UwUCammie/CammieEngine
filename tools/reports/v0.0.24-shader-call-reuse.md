# Shared shader call reuse performance

Local v0.0.24, 10 October 2026. This adds a shared engine shader transformation, with no chart, mod, authored shader or media edits.

## Implementation and bounds

`ShaderRepeatedCallOptimizer` recognizes adjacent scalar helper initializers whose repeated leaf calls use pure integer-coordinate functions. It composes small integer offsets and computes each identical call once, retaining floating arithmetic order and all sample coordinates. The prototype reduced 36 leaf evaluations to 16 per interpolation without changing the interpolation expression. Production recognition depends on syntax, types and purity, never shader, song or mod names. `ShaderSourceOptimizer` applies it through the existing shared shader-loading path after the prior nearest-distance reduction.

The pass leaves unsupported syntax unchanged. Guards cover side effects and unknown calls, global mutable reads/writes, derivative and texture operations, overload ambiguity, output parameters, recursion, conditional wrappers, macro interference, explicit precision/invariant qualifiers, coordinate mutations, intervening statements, ambiguous local types and excessive expansion. Generated locals stay inside the original block and avoid existing names. Floating expressions are not reassociated. Source size, group size, offset size, temporary count and purity-analysis call depth are bounded. No sample count, render resolution, animation rate or effect is reduced.

## Native fidelity

The original shader and candidate were rendered side by side with identical textures and uniforms at elapsed times 0, 1, 10, 80, 175, 230, 999 and 3600 seconds. The initial prototype, actual generic transformation and combined production transformations each produced zero differing RGB pixels across all eight captures. Each comparison covered 441,600 pixels after excluding the bottom 30 rows containing the existing MUTED overlay. The captured cloud image was also visually inspected. This demonstrates the tested shader/input cases on the current Radeon driver, not every possible shader or GPU.

The temporary comparator added raw-candidate loading and a single-view timing mode. Its source and binary were archived, and production source/executable/library were restored before experimental launches. The final production build contains the shared optimization with the original comparator. Authored donor shaders remain untouched.

## Isolated rendering

At 1280 x 720, two reversed-order original/prototype pairs measured steady-state GPU medians of 0.27084/0.27064 ms versus 0.23368/0.23362 ms, about 13.7% less GPU work for the isolated cloud-rendering fixture. The generic transformation measured 0.23416 ms. Samples begin after frame 120; each run retained more than 540 samples and skipped zero queries. This is whole-frame work for the isolated fixture, not a claimed whole-game improvement.

## Actual Try Harder gameplay

Matched 250-second native runs used the prior production binary (including the already accepted nearest-distance change) and the new production binary. Both ran muted on a never-activated private Windows desktop with all effects enabled, dimming disabled, a 60 FPS cap and a 1920 x 1080 gameplay window. The GPU context initializes at 1280 x 720; telemetry verifies the 1920 x 1080 resize before song start in both runs. All reported samples are from later gameplay. No builds, tests or independent hashing overlapped any timed run. Both completed successfully, with zero skipped asynchronous GPU queries.

Median GPU milliseconds per frame:

| Song interval | Previous build | Shared-call build | Reduction | Samples before/after |
|---|---:|---:|---:|---:|
| 10-60 s | 1.17190 | 1.09104 | 6.90% | 2984/2983 |
| 90-120 s | 1.06648 | 0.98628 | 7.52% | 1770/1767 |

The gain remains visible when later snowfall adds GPU load. These are GPU elapsed-query results around OpenFL rendering before presentation, not CPU frame time or an FPS claim. CPU/script hitches still occur, and this desktop result does not establish how the unidentified laptop GPU behaves. The actual-game comparison is one matched pair, supported by repeated isolated controls; it is not an alternating full-game series.

## Validation and remaining work

The final Windows build passed. Full suite: 2,758 tests across 929 modules in 368.6 seconds, 344 existing skips and zero failures. The full suite included the precision guard. A final 32-level purity-analysis limit was added after timing, and both affected shader tests passed again. Regenerating the representative shader with that final guard produced byte-identical output to the validated combined candidate; the final guarded Windows build also passed. The timed candidate binary is retained under `tmp/v24-noise-reuse/gameplay-candidate-bin`. The earlier Windows Application Control fixture failures did not recur in this suite. The new tests cover generic recognition under renamed functions, unique sample routing, integer offsets, floating expression order, block placement, collisions, idempotency and conservative rejection cases.

The laptop slowdown remains open. Continue with the remaining fog/snowfall costs and measured CPU/script hitches without lowering graphics quality. Preserve the separate large-import speed, residual final handoff, independent-package testing and every original roadmap goal. No release or push.
