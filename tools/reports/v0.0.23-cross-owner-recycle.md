# Shared source-class recycling checkpoint

Local development v0.0.23, 10 October 2026. Nothing pushed or published.

## Change

The shared source/native adapter previously accepted explicitly shared group members but rejected their class symbols during recycling. Recycling now uses the requested class's actual owner for construction and the member's actual owner for inherited class matching. Same-named classes from separate owners remain distinct. Factory-returned source objects retain their own owner, and positive-capacity groups still use native Flixel rotation, including its intentional disregard for the class filter at capacity.

Result conversion reuses the existing indexed-member adapter instead of duplicating identity logic. Released callers and class owners are rejected; factories cannot publish a member after releasing the participating caller or requested class owner. Changes apply to the common compatibility path used by source classes and Iris, with no chart/mod conditions or donor edits.
