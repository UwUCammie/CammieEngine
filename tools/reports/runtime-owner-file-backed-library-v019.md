# Psych owner-scoped Lime AssetLibrary runtime

The Psych owner asset facades can now load a receipt-verified v2 Lime identity sidecar into a private file-backed `lime.utils.AssetLibrary`. The library is built from the validated entry IDs, canonical Lime types, owner-relative paths, sizes, and target-derived per-entry preload flags. It never enters Lime or OpenFL's global registry. A declared owner library with v1 identity data, unknown load metadata, or an unsupported profile returns an explicit error instead of looking up a same-named host library.

The runtime caches one library and one load Future per owner identity and library name. Repeated calls share the in-flight/completed Future and library object. `unloadLibrary` and `removeLibrary` detach that local cache entry; the detached object remains usable while its original owner identity remains current, matching the behavior of a source library object retained after registry removal. A global availability epoch change triggers a fresh committed-proof check. If that owner still has the same transaction, index path/hash, scope, and receipt identity, its exact library and Future remain live; a changed or unavailable owner proof, or explicit owner release, invalidates it. The identity tracks live native views weakly and retires every current or detached view when its proof expires. The guarded `AssetLibrary` subtype rejects synchronous reads and gates all typed asynchronous results, including library preload, so stale callbacks cannot publish bytes after invalidation; stale completion also clears delegate caches.

OpenFL uses a wrapper around that same guarded Lime object, without `Assets.registerLibrary`, `Assets.unloadLibrary`, or global `onChange` registration. Both Psych facades first check an already-loaded owner Lime library for the requested ID, so its typed preload caches feed ordinary `get*` and `load*` calls. Image, audio, and font values are converted through OpenFL's usual Lime-backed constructors.

The implementation follows the pinned Lime `AssetLibrary.fromManifest`, `load`, typed getter/loader, and `unload` contracts in `.haxelib/lime/8,3,2/src/lime/utils/AssetLibrary.hx`; global registry operations are kept out of the owner path described by `.haxelib/lime/8,3,2/src/lime/utils/Assets.hx`. OpenFL's `AssetLibrary.__proxy` delegation and typed asset conversions are in `.haxelib/openfl/9,5,2/src/openfl/utils/AssetLibrary.hx` and `.haxelib/openfl/9,5,2/src/openfl/utils/Assets.hx`.

The loader currently accepts only verified `standard-file` profiles with a known target, complete identity and library inventories, a known library preload setting, and resolved per-entry preload values. It does not emulate Lime's generated-manifest startup registration for embedded libraries. Packed/custom handlers, source-path or generated libraries, MovieClip/class bindings, dynamic registration, and non-file-backed profiles remain explicitly unsupported. v1 sidecars retain identity lookup/list behavior but do not authorize library loading.

Focused Haxe eval checks passed for `test_psych_owner_asset_library_view.py` (1/1), `test_psych_owner_lime_assets.py` (1/1), `test_runtime_owner_asset_identity.py` (1/1), and `test_psych_owner_asset_library_lifecycle.py` (1/1). The identity test verifies that generation and availability epoch bumps reuse the same freshly revalidated owner identity, and that explicit owner release retires a detached view after it refills its cache. The view test delays a real Lime `AssetLibrary.load()` preload until after identity expiry and verifies that no result is published and the retired delegate cache is empty. The two-owner v2 retained-Project acceptance fixture verifies that an unrelated epoch change preserves the exact library view and load Future, then changes alpha's receipt proof and confirms alpha's old view fails while beta remains independent.
