# Named song loading work

The loading presentation now distinguishes chart reading from song-scene creation. The actual Freeplay preparation callback first runs only after its Reading chart framebuffer has rendered and flipped. Its existing nested transition request becomes a second deferred action: Creating the song scene must likewise render before that action can request the state switch. Duplicate accepts still cannot create a second transition. Aborted preparation, errors and authored source transitions retain their cancellation behavior.

The scene screen describes the chart already parsed: section count, chart-row count, embedded event-group count where present, selected stage, character identifiers and declared instrumental/vocal requirements. Rows include any embedded legacy event rows; they are not mislabeled as playable note heads. Long identifiers are shortened for display. These are known inputs, not completed asset counts. After atomic state creation, the ready screen reports actual generated note objects including holds, instrumental presence and the created vocal-track group size. The numeric X/4 label is removed; named chart/scene/ready status replaces it. The progress strip retains genuine lifecycle completions without a time estimate.

PlayState.create remains atomic. Owner-global scripts run near its beginning, character callbacks occur before native note generation, and Nightmare Vision note generation occurs later under different source hooks. Yielding between those calls would advance source timers/audio before later creation callbacks. This bounded change preserves that ordering instead of promising separately rendered music, character or note-generation percentages. Exit likewise honestly combines song cleanup and next-scene creation, which FlxGame performs in one synchronous state switch. Existing cache/audio retirement, source transition ownership, gameplay pause, viewport readiness and completed-frame retirement remain intact. Navy, animated stars, artwork matte and silhouette softness are unchanged.
