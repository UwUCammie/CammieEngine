# Nightmare Vision native scripted state wrapper contract

Audit source: `fnf_sources/NightmareVision`, revision `733165c42ca71eb0961a70e4173b2d81ba4a29ea`.

`NightmareVisionMusicBeatState` implements the donor's common state behavior on top of the host `FlxUIState`. It clears inherited host transition objects and delegates source transitions, owner controls, timing, persistent plugin calls, and state-local resource cleanup through `NightmareVisionMusicBeatStateHost`. The captured family session stays with the state factory; destroying a state releases its source script group and state-local views without releasing that session.

`NightmareVisionScriptedState` attempts script initialization in its constructor, binds the new module through the already-parented source group, and broadcasts `onLoad` before `create`. Its `create` calls the base lifecycle first and then broadcasts `onCreate`. If the module could not be initialized, the constructor still broadcasts `onLoad` to the empty group and `create` delegates to the host's source fallback callback, matching the donor's `FallbackState` path. This callback is expected to create the captured session's fallback state and route Confirm back to that session's MainMenuState.

The base preserves the donor's generic event order: source transition setup and `onStateCreate` plugins follow the native base create; each crossed step calls `onBeatHit` before `onStepHit` on beat boundaries, with scripts before persistent plugins; `onUpdate` runs after step handling and before native child updates; `onCloseSubState` runs before native close; and `onDestroy` runs before the script group is released. `Function_Stop` continues group broadcasting, `Function_Halt` stops that event's script broadcast, and neither value cancels native state work where the donor ignores callback results. `refreshZ` sorts with the shared live z-index adapter. `onCreatePost` and `onUpdatePost` remain explicit state-specific callbacks, as in the donor, rather than generic `MusicBeatState` events.

The focused fixture test copies the production state and group sources into a temporary Haxe project, supplies recording Flixel and interpreter stubs, and runs under `--interp`. It checks constructor `onLoad`, parent binding, transition clearing, create and update ordering, beat cancellation, state fallback after failed initialization, substate and destroy ordering, repeated destroy, and family-session retention for both created states and uncreated redirect candidates. The test passed on 6 October 2026. It does not certify a full game build, GPU rendering, or a native menu visit.
