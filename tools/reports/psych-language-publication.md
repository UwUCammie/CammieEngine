# Receipt-bound Psych language and media publication

Psych language and supported media mappings use one `SourceMappedMediaPublisher` plan for each authenticated source owner. The plan binds the retained Project profile to its exact source root, engine, namespace, and destination, then shares one receipt-verified walk and collision pass between the language and media policies. Nothing is published until the combined plan has completed. Both the normal owner importer and chart-free Psych global-pack importer publish through their existing staged, non-overwriting copy paths.

The language policy preserves authored targets ending in `.lang`, including case-insensitive extensions and non-language source files renamed to language targets. The media policy preserves Lime's authored target, `type`, `embed`, and `library` metadata. It handles the supported image/atlas, sound/music, font, shader, animation, and video forms documented in `source-mapped-media-policy.md`. `library` and `embed` remain metadata; the importer does not invent filesystem prefixes from them. Song/chart conversion and executable script collection remain on their specialized paths.

A complete profile is authoritative for its selected policy classes, so unmapped conventional language/media paths are not silently copied by legacy collectors. For an incomplete profile, receipt-verified enabled mappings remain additive, but their sources are blocked from duplicate legacy copies. Disabled, unresolved, and ambiguous projections suppress matching legacy source or destination paths. If an uncertain mapping overlaps a prior managed output, or an unknown scope could affect prior managed outputs, preparation fails before publication so the transaction can preserve the installed bytes. A source may still map to multiple distinct destinations; competing sources targeting one destination are not resolved by first-writer order.

Nightmare Vision uses the same planner with a caller-authenticated package or game/core scope. Package targets stay relative to their package owner; core targets use the owner's `__nmv_core` subtree. If a receipt-bound root cannot be proven to be either scope, the unresolved policy defers media instead of guessing. The legacy sibling-core dependency collector remains in place where a separate receiver profile has not been authenticated; this does not claim mapped publication across package/core owner boundaries. Lime asset IDs that differ from the authored target are deferred because no verified runtime alias index exists.

The global-pack copier consults the same policy views before its broader raw-tree fallback, so accepted, disabled, deferred, or otherwise explicitly blocked language/media files cannot re-enter through that path. The profile-unavailable case retains the existing legacy import behavior. No donor snapshot bytes or Project files are modified.

## Validation

Focused Haxe eval checks pass for `test_psych_language_publisher.py` (11 tests), `test_psych_global_pack_import.py` (2), `test_mixed_auto_import.py` (1), and `test_compat_script_import.py` (6). The extracted compatibility-script fixture supplies no-op policy seams because those tests exercise script collection independently; the real profile publisher is covered by the language and global-pack eval fixtures. The native retained-import probe is owned by the parent task and remains the integration check for the actual compiled importer.

The focused fixtures cover complete and incomplete profiles, exact owner/root binding, disabled and unresolved suppression, competing destinations, prefix and whole-owner uncertainty, engine aliases, cross-extension targets, tamper and prior-output preservation, staged byte identity, and the profile-unavailable legacy path. The global-pack fixture also checks authored source bytes, chart-free routing, and existing owner override preservation. Full-suite and native-build results are recorded by the parent task.
