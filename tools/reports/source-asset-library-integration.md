# Source AssetLibrary integration acceptance

The owner-scoped runtime exposes the retained Psych Engine library contract through `PsychOwnerLimeAssets` and `PsychOwnerOpenFlAssets`. A ready v2 source identity can build a detached Lime `AssetLibrary` from only receipt-verified entries for that exact owner and declared library. Repeated loads reuse the owner-local view and in-flight/completed Future. The OpenFL view proxies that same Lime library. Neither facade registers the source library in Lime or OpenFL's process-global registry.

The compatibility boundary is the file-backed subset recorded in the retained profile. The source target, library load profile, entry preload states, manager transaction, and file hashes must all be known. A missing target or unsupported load profile fails closed. The acceptance does not claim automatic `ManifestResources` registration, embedded startup visibility, custom library classes or handlers, bundle/movieclip decoding, or parity for other library bootstrap paths.

## Source basis

The pinned Lime source is `lime-8.3.2`, commit `d78d5be8a29de6ad649ffe4684ee435f76fe051b`. Its `AssetLibrary.fromManifest` constructs an instance from a manifest; `load()` runs preload work only for entries marked preload; `unload()` clears the typed caches. `lime.utils.Assets.registerLibrary` and `removeLibrary` mutate the process-wide named registry. The installed OpenFL source is version 9.5.2. Its Lime-target `openfl.utils.AssetLibrary` forwards calls through `__proxy`, and its manifest factory wraps a Lime library. The implementation keeps these instances private to a validated owner and library key.

The v2 sidecar preserves `loadTarget`, `loadProfileComplete`, per-library Project preload/embed metadata, and each entry's effective `preloadState`. Native source target is supplied by the caller as an exact build context; the host platform is not used to guess it.

## Prepared native check

The opt-in probe is `RuntimeOwnerLibraryProbe`, gated by `CAMMIE_OWNER_LIBRARY_SMOKE=1` and the existing runtime smoke gate. It imports two generated Psych roots through the actual scanner and retained manager, supplies explicit HTML5 contexts for those roots, and verifies receipt-bound Lime/OpenFL loads, warm versus lazy behavior, image pixels, same-name registry isolation, preloaded text/image cache reuse, owner release, and preservation of alpha's loaded view across a later unrelated owner's actual import revision. A separate pair of generated roots uses an explicit Windows source target and identical SOUND, MUSIC, and FONT IDs, including a Vorbis-backed `.ogg` stream. Alpha declares that OGG as MUSIC and beta declares it as SOUND under the same ID, proving that the source-compatible SOUND/MUSIC alias reaches the same path-based decoder. The probe compares decoded results with fresh Lime file decoders, checks Lime/OpenFL `useCache` behavior and asynchronous loads, tests missing and wrong-type failures, then changes sound, stream, and font bytes at the same source paths and verifies that the committed owner refresh replaces stale cached objects. For the OGG path, it compares the OpenFL streaming `getMusic` result's Vorbis metadata and initial PCM block with `VorbisFile.fromFile` on a hash-checked private copy of the exact committed bytes; it retains the previous stream across same-path refresh and verifies both old and new stream contents. Public `getPath` remains the original receipt-owned file, the source bytes stay unchanged by the lease, and library listing exposes only Project asset IDs. Lime 8.3.2 treats SOUND and MUSIC as compatible types in `AssetLibrary.list(type)`, so a MUSIC listing includes both mapped SOUND IDs as well as MUSIC IDs; it must still exclude FONT and private stream leases. Font decoder baselines use immutable private copies of the exact committed bytes, keeping the native `fromFile` comparison while avoiding extra handles on managed owner paths. Font comparisons include glyph IDs, advances and bearings, rendered dimensions and offsets, and every pixel for representative uppercase, lowercase, numeric, and descender glyphs. A third actual import omits build metadata and must produce an identity that rejects file-backed library loading.

The tracked source generator and runner are `tools/prepare_owner_library_fixture.py` and `tools/run_owner_library_native.ps1`; their generated fixture output remains under `tmp/`. The runner validates the typed-media fixture request, requires a separately prepared private runtime outside the checkout and an expected executable SHA-256, uses isolated smoke saves and muted audio, restores its process environment, leaves runtime evidence in place, and never edits a user installation.

## Windows native acceptance

`tmp/v19-release-native-accepted.log` records the final gated native success from the actual scanner and retained manager. It verified four roots across two actual imports: two explicit HTML5 contexts, two explicit Windows contexts, and a third uncaptured-target import that was rejected for file-backed loading. The run passed owner isolation, cache reuse, source failures, same-path changed-proof refresh, alpha and beta stream decoding, and owner release. The tested executable SHA-256 was `45dde13375c60d0bb9c5b227bc125816891b8fd71d28141aedb3ca308229857d`, built in `tmp/v19-release-build-accepted.log`. The isolated runtime was `C:/t/cammie-owner-library-v19-release-verified`; its event log was `C:/t/cammie-owner-library-v19-release-verified/tmp/owner-library-51198b25feb2.log`. The final fixture used the same OGG ID and path as MUSIC in alpha and SOUND in beta.

The generated source PNGs retain exact raw RGBA pixels and hashes. Routed OpenFL bitmap pixels equal a fresh pinned `BitmapData.fromFile` decode of the same committed PNG, element by element. No tolerance is used. OpenFL's native premultiplication can round semitransparent RGB channels, so raw PNG channels are asserted separately instead of treating that documented conversion as a compatibility error. Source hashes are alpha `6cf9dd59426cbfa87e3e6ae76f6ecca2552b6ee5d2c469a6f2e453333d6ef494` and beta `80189db98cc02a08dedc29f4cb4b556c1d8c256d23284fe154fa35c78e19e828`.

The final Windows run also verified the stream lease behavior during a real same-path refresh while the old Sound remained referenced: the old stream still decoded to its original PCM, the new stream decoded the committed replacement PCM, public `getPath` stayed at the receipt-owned path, MUSIC listings exposed only the Project audio IDs, and the selected source file remained unchanged. Font comparisons first render each sample glyph at 32 points, then compare the exact normalized glyph IDs, metrics, raster dimensions/offsets, and pixels. This is required because Lime's public `renderGlyph` changes the shared native face size, and the OpenFL Font wrapper shares the Lime face; the comparison fixes measurement scale and retains strict equality. The build was already underway when the fixture generator and its tests changed; those post-start changes were Python-only, while Haxe sources were frozen. Earlier rejected preparation runs remain diagnostic history, not acceptance evidence: one fixture lacked recognized empty data/song directories and one compared premultiplied OpenFL pixels to raw PNG channels. Their corrections preserved importer checks and exact pixel comparisons. Authored menu bootstrap, embedded/custom libraries, and bundle/class bindings remain outside this acceptance.
