# v0.0.30 library, difficulty and alternate-media checkpoint

All behavior changes are shared importer, engine, compatibility or host-menu code. No donor/chart-specific branches or donor edits. Native checks use muted private Windows desktops and isolated fixtures; the user's playing install is untouched. Nothing is published.

## Implemented behavior

- Receipt-validated identity archives reserve the source owner and original chart destination. The existing source identity rules require an authored ID or an authored/user name plus matching fingerprint. Reinstall selection reuses those reservations and fails on conflicting live ownership, damaged archive data/receipts or ambiguous matches. Favorites, categories, named difficulty, scores and history stay in their existing stores.
- Archive preparation uses strict retained and installed audits before its own recoverable transaction. This is not an uninstall executor: owner reservations, shared aggregate splitting, live-byte revalidation, registry removal and managed cleanup remain open.
- Sparse native `[time,lane]` heads count with zero sustain. This fixes missing native Erect notes in the prior analyzer.
- Difficulty uses 70% mean NPS and 30% the 90th-percentile ten-second density, plus a bounded danger contribution, scaled to the supplied nine-point color spectrum. Two-second peak NPS remains visible independently. Only ratings at least eight receive shadows. This is an FNF density estimate, not an osu! star-rating implementation.
- Every selected difficulty stays in a labeled grid with card expansion. Unselected cards stay compact. Displayed NPS, peak NPS and danger rate have exactly two decimals; stored values retain full precision.
- The shared import revision advances to five so retained imports regenerate the changed analysis and alternate-media outputs. Application version alone still does not trigger conversion.
- Chart-authored alternate song IDs can select separate instrumentals and split vocals within the selected source audio tree. Files publish with named difficulty suffixes and chart-local vocal metadata. Psych companion script discovery uses the authored formatted song ID. Breezy Plains Demon is the regression example, with separate audio and `data/breezy-plains-demon/cams.lua`; no chart-specific fix is used.

## Refresh measurement

Compiled Windows benchmark of the real cleanup methods uses 75 committed transactions in the private 25-package library. With their backup trees already absent, before times were 43.94, 41.51, 42.67 and 50.60 ms; after times were 2.38, 1.35, 1.24 and 1.19 ms. The fast path skips reconstructing/hashing historical backup paths; it does not skip receipt validation or recovery of interrupted transactions. This is a component result, not total startup/refresh throughput. Broader conversion/source-verification costs remain to profile.

Evidence: `tmp/v30-refresh-cleanup-benchmark/before.json`, `after.json`, `workload.json` and compiler logs. Existing backup cleanup/scheduler/recovery tests pass (20 cases, one environment skip).
