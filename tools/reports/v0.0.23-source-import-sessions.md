# Persistent owner-class import sessions

10 October 2026, local v0.0.23. No push, tag or release.

The existing class loader now supports a persistent owner session. Successive imports retain one descriptor registry, class-symbol identity and static storage. Native binding policy is copied when the session opens. Each incremental batch registers atomically: failed dependencies, aliases, partial sibling imports and module-budget changes roll back together. Earlier instances remain usable; corrected imports can be retried. Results are snapshots and released scopes cannot be revived. Existing one-shot loading retains its prior diagnostic/admission behavior through the same loader implementation.

Testing this boundary exposed a shared interpreter bug: unqualified static reads and writes inside source methods used instance globals, while qualified class access used owner static storage. They now share lexical class storage. Assignment, compound assignment, increments and writable value-type receivers use the same routing, while arguments and locals retain precedence. Static fields are not inherited in Haxe; inherited methods continue using their declaring class, and a child can have its own same-named static field. A compiled-Haxe comparison verifies this behavior.

Native testing exposed a second issue: ScriptClass.callFunction had an inferred return type that an integer comparison could specialize to Int, turning unrelated string-returning methods into zero on hxcpp. The shared dynamic-call boundary and its legacy fixed-arity wrappers now explicitly return Dynamic. Native verification runs numeric methods and the existing virtual/string-returning method probe in the same build. Both dependency changes are in the reproducible patch; idempotence is tested from clean upstream files.

The session fixture covers repeated imports, retained descriptors/symbols, qualified and unqualified static sharing, two isolated scopes, failed batches with successful dependencies, alias rollback, 100 rejected attempts without exhausting the module budget, corrected-source retry, native-binding snapshots, exceptional registration rollback and release. A separate Haxe oracle covers assignment, compound writes, pre/post increments, local/argument shadowing and declaring-class ownership.

## Remaining integration

This adds the persistent session used by the next bridge work; it does not yet enable arbitrary owner source classes in ordinary Psych HScript or runHaxeCode. Connect Iris through a shared source-object dispatch adapter rather than duplicating ScriptClass field/method semantics. Retain owner-session identity across the appropriate script lifetime, install existing stage constructor factories, and route source class construction/get/set/call/reflection with explicit native binding precedence and diagnostics. PlayState currently releases ordinary Psych interpreters before traversing stage destruction, so source stage scopes must survive that traversal before integration is considered complete.

Broader static initialization ordering/context and static method/value reflection are not certified by these checks. Retain all earlier invalid-state/reentrant/multi-scene cleanup, group-view lifetime, default-GF, countdown/end-song, dynamic-method, camera/transition and authored-menu acceptance gaps. All later imported-menu, management, categories/favorites, dense Freeplay, icon/star, independent sorting and fidelity-preserving performance goals remain required. Phase 2 and the full-roadmap release gate remain open.
