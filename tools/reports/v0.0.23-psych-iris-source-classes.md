# Psych Iris owner-class integration

10 October 2026, local v0.0.23. No push, tag or release.

Ordinary Psych HScript and embedded runHaxeCode now borrow persistent owner-class sessions from their gameplay state. Both use the existing source loader and HScript-ex object evaluator for construction, fields, instance methods, captured methods and lexical static fields. The lightweight SourceClassAccess interface keeps headless Iris users independent of the full source-class/Flixel implementation. Explicit native bindings retain precedence; conflicting source aliases and failed imports report their owner path without discarding earlier instances.

Core Type/Reflect operations now recognize source symbols and objects: resolveClass, createInstance, getClass, getClassName, field/getProperty, setField/setProperty and bound method calls. Explicitly shared objects resolve through their actual owning scope, while separate roots retain distinct class/static identity. This is limited reflection coverage, not complete Haxe reflection parity.

Closing an Iris script releases its interpreter while the state retains its class session. Existing stage construction registers nested source and native BaseStage helpers. The normal state stage traversal runs before class-session release, so surviving callbacks and authored cleanup do not lose their source evaluator when the importing script closes. Existing selected compiled-stage loading remains a separate owner scope; unifying its identity with ordinary imports is still open.

Native setup also exposed a pre-existing secondary-owner service bug: loading detached preferences called reloadVolumeKeys without a device adapter. Saved-data loading is now a shared operation separate from device activation. Public loadPrefs retains its reload behavior; language/services read stored data without borrowing global shortcuts. The preference test verifies both detached loading and the required public device operation.
