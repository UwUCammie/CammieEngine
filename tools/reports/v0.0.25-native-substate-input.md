# Native substate input regression

Local v0.0.25, 11 October 2026. Engine-level repair prompted by a report that the released pause menu opened but did not respond. The reporter could not identify an affected chart, so reproduction used the shared input path and the base tutorial; no chart or donor changes were made.

## Cause and shared repair

The source substate compatibility work changed `MusicBeatSubstate.controls` from `Controls` to `Dynamic` so Psych source substates could return their own facade. Native menu reads inherited that dynamic type. Compiled Windows pause reads used `__Field(..., paccDynamic)`, while the getter-backed Controls properties are returned only with `paccAlways`. Consequently the action getter was bypassed and the condition read false. The affected native readers were PauseSubState, GameOverSubstate, VictoryLoopState, SelectSongsState and CodenameModSwitchMenu. The latter also has raw keyboard fallbacks, so some keys could still work there.

MusicBeatSubstate now exposes a typed `nativeControls` accessor for native menus. Its dynamic script-facing `controls` getter delegates to the same live host controls by default; Psych source overrides remain unchanged. All five native readers use the typed accessor. The compiler now emits direct action checks for pause Up, Down and Accept. Controls bindings, keyboard/gamepad actions, frame caching and donor preference routing were not replaced.

## Verification

A behavioral regression extracts the actual control reads from all five consumers and executes them with getter-backed actions. It failed before the repair with `PauseSubState input getter was bypassed`. Afterward it passes across press/release/press changes, replacement of the active Controls object and a source facade override. Focused source substate clock and input tests also pass.

An opt-in smoke observer dispatches keyboard down/up events through the existing OpenFL stage input helper, reads the real pause selection and checks actual audio state. The production Windows build ran the base tutorial muted on a never-activated private desktop at 60 and unlimited FPS. Each process opened pause with Escape, moved down to Restart Song, moved up to Resume and accepted with Enter twice. All four cycles passed. The song clock remained frozen during the navigation and music resumed afterward. These are native input-routing checks, not a GPU performance comparison; the full suite was running concurrently. They do not certify every imported custom pause menu.

## Final regression gate

The canonical Windows build passed. The full suite ran 2,775 tests across 933 modules in 439.8 seconds with 344 skips. Its sole failure was an extracted game-over-method fixture still declaring the old `controls` field; it was updated to supply `nativeControls` to match the intentional host API change. All eight affected/related tests then passed, including all four tests in that module, the new native-control regression and source substate lifecycle checks. No production code changed after the successful native build or pause runs. No unresolved failure remains.

The capped run observed 61 FPS at its peak; the unlimited run observed 4,649 FPS. Both passed two complete navigation/resume cycles. Protected-file verification found no new changes among the 70 baseline files; the only difference remains the previously authorized private visual-test options baseline. Text-policy and diff-format checks passed.
