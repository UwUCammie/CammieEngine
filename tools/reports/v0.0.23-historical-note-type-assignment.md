# Historical NV note-type assignment

Local v0.0.23 development; no push or publication.

## Source contract and implementation

Compared with Nightmare Vision revision 7f96eb3b5a60352413229bf134bd348b79ad5fe6, source/gameObjects/Note.hx set_noteType. The production Note getter/setter and initial-generation adapter now run against the pinned setter in the regression fixture, rather than relying on a simplified assignment model.

The requested type is separate from the current visible type. Defaults and attachment clearing happen first. A changed type captures its script and runs setup with the old type visible. The type commits only after setup returns, then splash HSV captures the final callback values. Nested assignments commit independently: the outer type commits last while the inner script attachment remains. Assignment eligibility is captured before callback execution, so a callback changing noteData does not retroactively prevent the commit. Repeated same-type assignments still reset defaults and clear the script without rerunning setup.

First generation now presents the source empty type while the authored type's setup executes. Repeated skin configuration preserves the completed assignment. The shared runtime retains one callback and interpreter path; modern note dispatch remains unchanged. Native historical commits bypass the other source profiles' type setter effects. Source built-in Hurt, No Animation, GF Sing, Ghost and Slam type effects run at their historical positions, including Hurt reload before miss-health and hit-causes-miss assignment. These are source engine type names, not chart-name exceptions.
