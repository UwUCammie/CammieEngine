# v0.0.32 live HXC Freeplay routing

The host browser can refresh chart data and imported callback routing without replacing the menu. `HxcFreeplayRuntime.refresh` rebuilds committed manifest associations and precedence while keeping the current menu's interpreter objects, variables and native-resource references. Once initially loaded, it does not rediscover or execute module programs. Changed, new and previously rejected module code is considered on the next natural menu entry, without forcing the current browser to reopen.

This lifetime choice follows actual capabilities: a real `HxcCompat.analyze` probe accepts a Freeplay `subStateOpenEnd` callback which starts a native `FlxTimer` (`moduleSafe` and initialization both true). The interpreter does not own all display objects, timers or listeners such callbacks can create. Re-execution could duplicate resources; clearing variables during live refresh could break existing timer closures. Routing-only refresh avoids both operations.

Availability changes park pending owners immediately. Their manifests/modules are not read during live refresh, runtime dispatch and retained proxies return no result, and a parked higher-priority module continues to block a weaker fallback. Once ready, committed routing is adopted and the old snapshot can resume. A separate known-owner predicate distinguishes pending owners from removals. Removed owners remain disabled for the rest of the current menu, including after the same path is re-added; their variables survive until normal runtime disposal.

The Freeplay caller supplies current root readiness, song readiness and known-owner predicates at construction and reconciliation. Parking governs this runtime's dispatch and module proxies; already scheduled native callbacks are not intercepted or automatically cleaned up. This does not introduce a general filesystem read lease, certify arbitrary escaped closures, or extend the existing translation safety gate.

Focused verification: five live-refresh fixtures use actual HScript interpreters and retained proxies, with filesystem/discovery and translation-boundary stubs. They cover unchanged snapshot state, changed/new/rejected code deferred until natural reentry, pending-owner read suppression and resumption, updated manifest associations/precedence, parked-primary fallback blocking, removed/re-added owners, preserved variables and disposal. All five pass. The existing five routing tests pass; the final-source foreign-runtime integration completed 19 cases (18 passed, one environment-dependent skip).

Final native verification passed at requested 60/480 FPS caps: the same-state Freeplay probe retained state, camera, music and unchanged row/icon/star references through reorder/insertion and empty-list/readdition, with the final title-anchor correction also reviewed. Its generation update uses an isolated synthetic metadata change, not a complete real archive import. See [Freeplay motion and reconciliation evidence](v0.0.32-freeplay-live-motion.md).

The real Freeplay-to-Breezy Plains Demon-to-Freeplay loading check also passed. Chart, scene, ready and exit work phases rendered in the required order, and their actual details/readbacks were inspected. See [loading phase evidence and limits](v0.0.32-song-loading.md).

The integrated run completed 2,848 tests across 964 modules in 641.5 seconds, with 347 skips and two failed modules containing obsolete extracted fixtures. Tests-only corrections resolved both on canonical scoped reruns: UserLibrary passed 10/10 in 3.4 seconds and CategorySearch passed 5/5 in 0.5 seconds, with no skips or failures. The 40 focused Freeplay checks also passed. All reported failures are resolved; this does not describe the original integrated run as failure-free.

Requirements remain in `IMPLEMENTATION_ROADMAP.md`. Controller coverage, real archive-import stress testing and the previously stated script/resource limits remain open. Nothing was published as part of this change.
