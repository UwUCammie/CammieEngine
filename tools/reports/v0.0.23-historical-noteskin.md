# Historical NV noteskin startup and live offsets

Development v0.0.23, 9 October 2026. Shared engine and compatibility changes only, with no mod/chart conditions or donor edits.

## Implemented contract

Reference: Nightmare Vision revision `7f96eb3b5a60352413229bf134bd348b79ad5fe6`, PlayState noteskin initialization, Paths.noteskin/modsNoteskin and final note/receptor positioning.

The historical owner profile now initializes three per-key FlxPoint arrays before stage scripts load. Noteskin lookup interleaves owner mod and core paths by source extension order. Historical noteskin paths remain script paths; modern JSON noteskin resolution is unchanged. The default branch attempts the first extension, as in the source. A missing script uses default textures instead of trying to read a missing file.

The existing owner-scoped interpreter loads the module and supplies the live arrays to its offset callback. The main script registry owns subsequent update/destroy calls. The bfSkin, dadSkin and arrowSkin callbacks run after registration in source order. Historical texture IDs use the shared noteskin renderer rather than being interpreted as JSON skin names. A parse-failed, unregistered module is explicitly released.

Historical gameplay adds strum offsets to receptors, sustain offsets to holds and note offsets to all notes after modifier positioning. The callback reads current arrays each frame, including replaced arrays, without accumulating offsets. Public modifier updateObject retains its own source contract and modern rendering ignores these arrays.
