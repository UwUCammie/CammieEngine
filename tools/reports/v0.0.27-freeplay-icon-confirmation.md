# v0.0.27 Freeplay icon confirmation

12 October 2026. Shared menu presentation and launch flow only; no donor content edits.

## Behavior

HealthIcon's menu pixel-portrait path now checks the matching owner-scoped XML
before loading the PNG. A supplied atlas displays individual frames, not all faces
at once. The source idle, confirm and confirm-hold clips play at 10 FPS, matching
the local Funkin PixelatedIcon contract. Numeric frame ordering and filename
suffixes are preserved; confirm-hold frames never join the one-shot confirm clip.
Missing idle metadata falls back to a single atlas frame, not an entire sheet.
Generic animated health-icon atlases retain their normal/dying/winning/poisoned
clips and gain menu-only confirm/hold clips when supplied. Gameplay icon state and
bop logic are unchanged.

Host Freeplay browsing stays in the normal animation. Enter starts an authored
confirm clip, otherwise winning, otherwise losing, otherwise neutral. On static
strips, a winning slot that duplicates neutral is not treated as an authored
winning face. Finished confirms use an authored hold clip when present. HealthIcon
exposes the same confirmation operation for imported capsule callers.

The dense host browser waits for the confirmation presentation using elapsed time
(0.35 seconds minimum and two seconds maximum). Repeated accept does not rearm it.
Back cancels; navigation/search/library input cancels and proceeds normally.
Selection/difficulty identity, selection generation, state destruction and current
package readiness invalidate stale actions. A completed action goes through the
same launch helper as imported capsule/default-menu routes and performs a fresh
readiness and actual-chart check before loading. A random selection retains its
resolved target rather than choosing again after the animation. Imported custom
menu callbacks retain ownership of their own confirmation flow.

## Validation

Two focused compiled checks pass frame selection/order, hold completion, normal
reset, winning/losing/neutral fallbacks, 30/60/480/2000 FPS action timing,
cancellation and one-shot ownership. An extracted-method fixture exercises the
actual menu action and shared launch methods with Back/navigation cancellation,
changed difficulty, pending packages, stale readiness, removed chart and resolved
random target/score identity cases (`tmp/v27-confirm-focused.log`).

Canonical `run.bat test` built Windows and ran 2,792 tests across 940 modules in
398.9 seconds, with 344 skips and three failing fixture modules
(`tmp/v27-confirm-full-test.log`). All three are corrected and passing on scoped
reruns: the score test expected duplicated launch code instead of the new shared
function; the collision-name test pinned the old V-Slice revision instead of its
required minimum; the sentinel test's broad extraction included new unrelated
instance methods. See `tmp/v27-confirm-score-recheck.log`,
`tmp/v27-confirm-collision-recheck.log` and `tmp/v27-confirm-sentinel-recheck.log`.
The complete suite was not repeated after these fixture repairs.

The final incremental build passed with numeric atlas ordering and the corrected
native-probe layout refresh (`tmp/v27-confirm-final-build.log`). Private-desktop
native runs at configured 60 and unlimited FPS passed real owner-scoped PNG/XML
loading, idle frame selection, animation completion into confirm-hold, cancellation
on selection changes, visible confirmation before one-shot launch, and gameplay
return. The probe generates private runtime art and does not modify donor graphics;
its colored frames are diagnostic fixtures, not production portraits. It preserves
the private save payload and options. Final logs:
`tmp/v27-confirm-final-native60.log` and
`tmp/v27-confirm-final-nativeuncapped.log`. Both report `iconConfirmation:true`
and success, and both test processes exited. These runs are functional checks,
not FPS benchmarks; background import work was active.
