## Source contract and implementation

Donor `funkin/game/modchart/ModManager.hx` registerMod/setValue stores actual note/misc instances, maintains live active-name arrays and resolves the note-map instance during each position/object pass. getPos checks current object activity and name exclusions on every step, accepts an optional vector and adopts replacement vectors. updateObject sets native position before ordered callbacks and performs centering/type offsets after them. Modifier values and its independent active flag are separate concerns. ScriptedModifier owns the interpreter callback receiver; manager/instance/interpreter integration is implemented and validated by the other owner.

The retained registry identity can finalize keys/players without losing existing values. Its source-mode bridges delegate values, aliases, activation arrays and current instance resolution to the manager. Standalone formula use retains the prior builtin cache and behavior. The timeline dynamically enrolls registered names without resetting existing schedules.

Transform execution interleaves existing builtin formulas and custom instance callbacks in the manager's actual active array. It checks live native activity before each step and excludes names before resolution. Builtin values come from the resolved instance when provided, preserving note-map values even if a same-name misc registration replaces the global map. Scoped formula-instance bindings restore on exceptions and nested requests.

The renderer supplies the actual native note, receptor, note splash or sustain splash. Intermediate flush/read boundaries transfer current x/y/scale/angle/alphaMod/multSpeed/RGB fields without premature centering or skin offsets; arbitrary native properties are untouched. Final source centering/type offsets follow callbacks. Note path time is strumTime, its sustain endpoint uses strumTime plus segment duration, and receptor/splash time is zero. Replacement positions retain their identity through the pass. Pinned PlayState puts only the sustain nextPos after clipping; head and receptor/modchart returns are not put. The renderer preserves head/receptor replacements and uses a pooled source-mode sustain endpoint whose returned vector is put after final use. Standalone formula scratch storage remains retained. The vector implementation and pooling surface are owned by the integration agent.

Public renderer evaluatePosition and applyObject support the source manager API. Each creates a fresh request object over retained baseline data so a recursive excluded request cannot overwrite an outer snapshot. applyObject does not implicitly evaluate position. Source manager application uses type offsets; the gameplay renderer separately applies selected skin offsets. Owner context/delegates remain manager/PlayState integration work.
