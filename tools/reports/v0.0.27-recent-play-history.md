# v0.0.27 recently played library order

12 October 2026. Host library and shared song-start lifecycle; no chart/mod edits.

## Contract

Recently played is a chart-order choice, independent of mod/engine grouping and
group ordering. A song enters history after its shared PlayState start path has
started audio and finished start callbacks. Normal Freeplay, imported menu and
Story Mode launches use the same hook. Browsing, previews, confirmation, modifier
menus and canceled loads do not record history. A guard records at most once per
PlayState instance; a real restart creates a fresh instance. This is a play-start
record, not a claim of completing the chart or earning a score.

LibraryChartIdentity shares the existing lazy receipt and owner resolution with
Freeplay. UserLibraryData.resolvedChartKey shares the retained owner/source-folder
key rule. The existing score identity preserves selected row casing before
resolving this key. Missing imported ownership cannot fall back to a base-game
record. Namespaced destination names and renamed display labels do not merge
separately owned songs. No new package scan or importer revision is needed.

The separate host library save stores an observed timestamp plus a monotonic
numeric sequence. Recent ordering uses that sequence, so tied timestamps and clock
rollback do not move a newly played song backward. Zero means no observed play;
unknown songs sort after known plays, using registry order and stable IDs for ties.
Grouping remains contiguous and chart/selection/readiness indexes do not change.
Preference/history transactions invalidate the browser's existing order cache.

Version-one saves without history migrate to an empty history, with no invented
plays inferred from scores or filesystem dates. Decode rejects nonnumeric/nonfinite
values, fractional/out-of-range sequence numbers and duplicate keys/sequences.
Numbers remain exact through the supported double-integer range, without 32-bit
narrowing. UserLibrary's existing flush-before-publish transaction preserves the
old save/model after failure. History errors are reported and do not stop playback.

## Validation

Focused Haxe checks cover migration, grouped/flat recent ordering, tied clocks and
rollback, large sequence values, malformed history, retained identity, repeated
start calls, fresh-instance replay, unresolvable imports and failed saves. The real
UserLibrary save transaction also verifies that a failed history write leaves both
its published model and disk value unchanged. The source hook is checked after
audio playback, and the native library navigation probe checks no history before
launch and one persisted record after a real song start and menu return.

Canonical Windows build and full regression suite passed: 2,798 tests across
943 modules in 426.2 seconds, with 344 existing environment/fixture skips and zero
failures. The final header/shared-label and stronger native assertion refinement
also built successfully. Two extracted browser sorting tests and ten library
save tests passed, including real flush rollback for play history.

Final muted private-desktop native runs passed at 60 and unlimited FPS, using the
same final executable. They check canceled confirmation leaves history empty,
a real song start creates exactly one persisted record, an unplayed imported
favorite keeps no history, and switching from descending alphabetical order to
recent order actually moves the played song while retaining selection/difficulty.
The flat-list header shows the active order using the same labels as the controls.
The final 60 FPS recently-played capture was visually reviewed. Existing global
favorites/categories, gameplay return, package badges and independent sorting
checks remain green. Settings and the private save are restored by the test;
these are functional checks during fixture import refresh, not FPS benchmarks.

must not masquerade as a new installation; older unknown import times must remain
unknown. Comparable score/rating sorting, explicit donor-order acceptance, broader
refresh/reinstall, physical controller and user visual review gates remain open.
