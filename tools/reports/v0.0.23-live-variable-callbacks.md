# Live source variable callbacks

Local v0.0.23 development. Full-roadmap publication gate remains in force.

## Source contract and implementation

Psych revision `5c67ced49e5a98535298a6daa3f8f4ec79ac8399`, FunkinLua/HScript callbacks, uses MusicBeatState.getVariables on each invocation. Lua getVar reads directly. HScript getVar/removeVar check existence and then resolve the registry again; removeVar returns true once existence was established, irrespective of the later remove result. Lua setVar resolves its destination before parsing the value and returns the original input. The existing Lua removeVar extension retains its direct remove result.

The shared SourceScriptVariables service implements those ordered operations. Psych source adapters select the live native registry; historical NV's existing compatibility overlay keeps its owning gameplay registry. This does not change the separate historical text namespace.

Current NV revision `733165c42ca71eb0961a70e4173b2d81ba4a29ea`, FunkinScript.preset, binds global to the initial PlayState.variables map but resolves PlayState.instance.variables each time setVar/getVar is invoked. The production gameplay binder now supplies that live singleton provider. Psych's input-returning setter and NV's void setter share the write operation while preserving their different results. A direct source-expression comparison caught an early implementation leaking the Psych return value through the NV wrapper; the shared write operation corrected it.

## Evidence and limits

The Psych differential oracle extracts five callbacks from the pinned source and compares 80 call-order/result cases, including missing values, repeated provider lookups, registry changes during exists or conversion, and a false remove result after successful existence. Conversion is an injected operation in this oracle; this proves destination/conversion order, not full instance-marker parsing.

The NV public binding test now retains cached functions, changes the live provider, checks writes and reads reach the new map, checks global retains its initial map, and compares the reflected setter result against the exact pinned source expression. Existing focused binding tests also passed.

Native probes exercise public Lua/HScript callbacks after a synchronous temporary active-state change, NV callbacks after replacing a disposable PlayState singleton, and historical owner isolation. They restore all pointers, flags and maps. They do not prove real state creation/destruction, retained callback teardown or complete menu transitions.

## Remaining work

Audit Psych instance-marker parsing against parseSingleInstance: the current compatibility path performs recursive parseInstances and owner/tag-aware lookup, while the pinned Lua setVar uses a single-instance parser with PlayState.instance/class traversal. Do not silently generalize the registry result to those different semantics. Direct/nested object helpers, sprite/text constructor registry providers, source-class construction, exact lookup precedence, global-provider diagnostics and full lifecycle/teardown remain open. Current NV and historical profiles must retain their source-specific roots and returns. All previously recorded compatibility, menu, library, Freeplay, sorting and fidelity-preserving performance requirements remain required.
