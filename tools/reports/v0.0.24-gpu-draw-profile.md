# Try Harder GPU draw-cost attribution

Local v0.0.24 performance investigation, 10 October 2026. This is diagnostic evidence, not another production speedup. The laptop bottleneck remains unresolved. All broader roadmap goals remain required.

## Measurement and isolation

Two native hard-chart gameplay runs completed successfully at a 1920 x 1080 window and a 60 FPS cap, with all shaders/effects enabled and dimming disabled. Audio was muted and both ran on a never-activated private Windows desktop. No build, test suite, import workload or file hashing overlapped either timed run. The machine remains the Radeon RX 7900 XT used for the existing whole-frame baseline.

A temporary compiler build macro wrapped the two pinned OpenFL Context3D draw submission sites with the existing nonblocking native GL_TIME_ELAPSED queries. It samples one frame in 30, using a bounded 1,024-query pool and checking result availability before reading. No queries were skipped. This measures drawElements/drawArrays work only, excluding clears, uploads, state changes and presentation. Query overhead means the sum is not interchangeable with the prior whole-frame measurements or a claimed new speedup. The small draws sometimes fall below timer resolution.

The initial attempt to instrument the dependency directly was rejected by the existing pinned-source guard. The exact dependency was restored and instrumentation moved to an explicit temporary compiler macro; the guard was not disabled. The first completed run established costs but OpenFL's Program3D source fields were empty for runtime shaders. The second diagnostic retrieved actual linked fragment sources from the driver, saved them, and verified their SHA-256 identities in the summary. It completed successfully with zero skipped queries. Matching dominant costs across both runs support the attribution.

Before each launch, the original Project.xml, RuntimeGpuProbe source and production executable/library were restored byte-for-byte. The diagnostic executable remained isolated under tmp. The pinned Context3D source is also byte-identical to its saved original. No authored chart, stage, shader asset, donor, playing installation or saved game setting was changed. The private options file was restored by the launcher.

## Results

Median GPU milliseconds per sampled frame for each identified program:

| Song interval | Sampled frames | Worley/Perlin cloud | Simplex fog | Snowfall |
| --- | --- | --- | --- | --- |
| 10-60 s | 99 | 0.54432 | 0.37920 | Inactive |
| 90-120 s | 59 | 0.53972 | 0.37620 | Inactive |
| 180-240 s | 115 | 0.54500 | 0.37752 | 0.39480 |

The cloud and fog programs account for 79.4% of summed measured draw time at 10-60 seconds. The snowfall program becomes another major contributor later. Program identities come from the actual linked GLSL: program 2 contains the Worley/Perlin fractal-noise functions, program 4 contains simplex fBm, and program 9 contains the authored particle-loop snowfall. Labels are for reporting only; no gameplay or optimizer branches depend on a shader/mod/chart name.

## Next implementation target

Evaluate shared compiler-level specialization of simple uniform-bound integer loops. The later snowfall pass currently executes a uniform 30-iteration loop per fragment, including index-dependent calculations. A bounded expansion may let the driver fold more index-dependent math while retaining every iteration and the original fallback loop above the expanded range. This is a candidate, not a validated fix: reject unsafe control flow, index mutations, alias/macro ambiguities and shader code growth; retain compilation fallback. Native fixed-input pixel comparisons must establish negligible visual differences, because driver constant folding of trigonometric/hash functions can change results. Timed whole-frame and per-pass comparisons must show a worthwhile gain before enabling it.

Cloud/fog computation remains the larger early-song cost. Continue investigating shared algebraic/compiler or rendering improvements without reducing samples, resolution, animation rate or disabling effects. Do not treat these desktop timings as proof of performance on the unspecified laptop GPU.
