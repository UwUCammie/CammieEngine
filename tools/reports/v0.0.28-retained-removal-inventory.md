# Strict retained ownership inventory

## Problem and change

The browsing helper `ImportRefreshManager.cachedRecords` intentionally skips missing or invalid records. Feeding that list into a deletion assessment could omit a surviving shared owner and incorrectly treat its files as exclusive.

`ImportRefreshTransaction.inspectRetainedManifests` enumerates both retained pointer files and transaction-owner directories. Every committed owner must have a matching pointer, every pointer must have committed state, and the current manifest must match its receipt and completed transaction. It uses the existing transaction manifest, receipt, path and cancellation helpers. It neither invokes recovery nor creates missing cache folders.

Incomplete, corrupt, foreign-install, unexpectedly named or linked metadata is rejected. A malformed newest journal cannot fall back to an older phase. Fully rolled-back first imports can be ignored because they have no committed manifest or installed file claims. Entry and byte budgets bound metadata inspection, and captured file digests/directory lists are rechecked for changes during the read.

The native library lifecycle probe now supplies this strict inventory to `ImportRemovalPlan` instead of the browsing cache.

## Validation

The executable Haxe fixture uses real `ImportRefreshTransaction.apply` commits, then exercises 16 scenarios: empty installation, valid owners, missing manifest, hidden owner, pointer without state, malformed pointer, corrupt/missing receipt, manifest digest mismatch, unexpected state/record entries, malformed latest journal, foreign installation, cancellation, metadata changes during inspection and a rolled-back first import. Failure-path snapshots verify that inspection does not modify files. These and the existing removal-plan contracts pass.

The corrected Windows build passed. Muted private-desktop native probes passed at 60 and unlimited FPS using actual generated-package imports. They verified strict inventory, read-only assessment, active-owner blocking and moved/repeated source identity preservation. Both probe executables match the final build. Evidence: `tmp/v28-removal-inventory-native-proof.json`, `tmp/v28-removal-inventory-final-build.log` and `tmp/v28-removal-inventory-tests.log`.

The first native attempt exposed an incorrect fixture assumption: real pointer files contain only an `id`, while schema information lives in the committed record. The reader and fixture were corrected to this format. The initial full suite was invalidated by that source edit during native fixture fingerprinting and was explicitly stopped. It is not counted as passing evidence. The fixed-source full suite completed 2,808 tests across 949 modules in 1,170.5 seconds, with 347 skips and one dependency-resolution test timeout. The entire seven-test dependency module passed on isolated retry in 79.769 seconds (one existing skip). Three additional compiler-PATH skips were covered by a six-test supplemental run with the bundled compiler; all six passed. The remaining 344 skips are existing platform/corpus limitations. No assertions were weakened or tests excluded.

Logs: `tmp/v28-removal-inventory-final-suite.log`, `tmp/v28-dependency-roots-retry.log` and `tmp/v28-path-compiler-supplement.log`. Whitespace and engine text-policy checks pass. The invalidated initial suite remains in `tmp/v28-removal-inventory-build-suite.log` for audit. The user's playing installation was not modified; all native runs used generated private fixtures.

## Remaining removal work

This API establishes a strict inventory of retained transactions only. It is not a complete legacy/unmanaged asset audit, an atomic execution lock, a removal command or a deletion UI. Before exposing uninstall, reconcile installed package/chart provenance with this inventory, reserve all affected owners and paths, revalidate current bytes under the transaction guard, archive identities for reinstall, split aggregate transactions per package, reconcile registry contributions, and journal commit/recovery/cleanup. Keep shared assets and external donor folders intact. Preserve saved history by default, with a separate explicit erase-history action.

## Next implementation boundary

Audit installed chart/package provenance against these retained manifests so legacy or unclaimed owners cannot be hidden by a complete retained-cache listing. `LibraryChartIdentity` and `ImportSongOwnership` currently derive identity from live `importProvenance.json` files; archive validated identity/fingerprint bindings separately before removing those files. The transaction manifest currently records transaction-level ownership, so deleting one package from a multi-root receipt still requires proven per-package ownership splitting. Do not solve that by silently expanding a one-mod deletion into deletion of the entire aggregate.
