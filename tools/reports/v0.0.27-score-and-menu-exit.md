# v0.0.27 score markup and song exit checkpoint

## Scope

Shared engine/compatibility changes only. No chart, mod, shader, atlas or donor files were edited. No release was published.

## Accuracy colour

Nightmare Vision applies an orange FC format range to its native score label. The bundled results provider subsequently writes a differently arranged score string, leaving that character range over accuracy digits. The engine score label now owns its native format and retires only that format when its text changes. Equal text keeps its rank formatting, authored formats survive, and a subsequent native HUD update can apply its current rank again. Authored replacement FlxText labels retain the previous adapter behavior.

Executable tests cover reflective script writes, rank changes, missing/invalid ranges, cleared text, and 1,000 repeated competing refreshes. The native Windows probe also verifies range removal while retaining a separately authored format.

## Exit timing

The engine menus previously decoded their entire music track during state creation. They now use the shared local Vorbis streaming loader already used by the NV asset facade, with the ordinary sound loader retained for unsupported formats/platforms and unsuccessful stream creation. Each stream owns a separate playback cursor. Failed partial opens release their decoder. Gameplay cleanup, bitmap-cache clearing and authored presentation are unchanged.

Measurements used the same instrumented Windows binary and private runtime, retained NV Accelerant, pause after about five seconds, a 1920x1080 window, 60 FPS, full shaders and no background/highway dim. Each destination ran decoded/streamed/streamed/decoded in fresh sequential processes, with no concurrent test suite. All windows ran muted on a private never-activated desktop. Options were restored after every run. The decode control invokes the previous getSound path and is available only through the explicit smoke probe.

Times are request to first destination draw. Windows timer resolution is approximately one millisecond. These are local measurements, not laptop guarantees or cold filesystem benchmarks.

| Destination | Previous decode path (ms) | Streaming (ms) | Median reduction |
|---|---:|---:|---:|
| Main Menu | 266-278 | 153-154 | 43.6% |
| Options | 353-359 | 191-193 | 46.1% |
| Freeplay | 294-297 | 143-165 | 47.9% |

Music loading itself fell from 124-151 ms to 2 ms. Both paths reported identical track lengths (112,953 ms for Main Menu/Freeplay and 157,988 ms for Options), advancing playback clocks, active playback and looping. Muting remained enabled. First-draw measurements precede background refresh work that can resume in the menu.

Remaining song teardown and menu construction still take time. This checkpoint removes full-track decoding from those transitions; it does not claim zero-latency transitions or resolve every roadmap performance item.
