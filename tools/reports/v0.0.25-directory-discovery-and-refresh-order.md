# Windows script discovery and persistent refresh order

Local v0.0.25, 11 October 2026. Shared engine/importer changes only. No donor, chart, shader or mod assets changed; no publication.

## Directory discovery

`NativeDirectoryListing` reuses Win32 directory enumeration attributes instead of separately querying every entry. Reparse points remain live filesystem queries when visited. Partial or failed native enumeration falls back to the existing portable API. Relative, drive-rooted, extended-length and Unicode names retain their existing semantics. Empty and drive-current-directory forms use the portable path. No filesystem data persists across scans. HXC discovery retains its sorting, depth and file limits, full paths and source-family classification.

The earlier execution block no longer reproduces with the correct compiler runtime DLL directory on PATH. No signing, allowlisting or other security setting changed. This does not establish that every previously blocked executable is permitted.

Native final-source comparisons traversed the same 36 roots in reference/candidate/candidate/reference order. All path, chart, global, other-song, unknown and per-family arrays matched exactly. Reference durations were 0.753769 and 0.805228 seconds; candidate durations were 0.339984 and 0.333299 seconds. This is directory/script discovery work, not total import time or GPU time. Thirty-five roots contain no HXC files; the native fallback root contains eleven. Traversing their media-heavy directories is still part of the existing menu path.

Seven filesystem tests pass, covering Unicode including supplementary characters, mutations, empty/missing/file roots, relative and drive-rooted names, paths beyond 260 characters, file-like directory names, file/depth limits and junctions. Test output uses the existing Unicode-safe serializer; the initial ordinary JSON printer corrupted surrogate pairs while native enumeration itself matched the portable implementation.

## Independent-package refresh evidence and ordering fix

The unchanged v0.0.24 diagnostic completed the previously pending 25-package refresh on a muted, never-activated desktop. It covered 35 roots, 263 imported songs and 54,553 owned paths in 950.070 seconds from launch. Every receipt and output hash verified. Readiness observations include 118,942 blocked decisions and 467 intervals where completed songs were available while other packages remained pending; every final row was ready. Maximum sampled frame gap was 1,917 ms and maximum update/draw duration was 123 ms. This is a baseline, not an optimization result. Completion and a following frame are not necessarily captured by the same timing sample.

That run failed the semantic acceptance gate: all 263 imported rows moved during package refresh, although song metadata stayed identical. The converter removes its owned rows in staging and appends regenerated rows. Shared publication now preserves surviving Freeplay row positions after normal ownership, conflict and concurrent-edit validation. It keeps regenerated values, deletions and new-entry slots. Ambiguous or primitive arrays are not reordered. The helper reuses existing registry identity and equality rules and applies only to the shared Freeplay registry paths.

The new transaction regression failed before the fix and passes after it. Three independently installed packages refresh repeatedly in a different order while retaining row order and accepting changed metadata. Related foreign-row, concurrent-owner and local-conflict tests pass. A native replay against the actual 263-song before/after registry restores exact semantic equality, including array order. This real-data replay is not a second complete 25-package refresh.
