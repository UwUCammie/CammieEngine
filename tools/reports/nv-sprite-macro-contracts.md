`NightmareVisionSpriteMacro.build()` generates actual public loadFromSheet, loadAtlasFrames, makeScaledGraphic, setScale and centerOnObject delegators. Signatures/defaults and FlxSprite return type retain the source base semantics; every return preserves receiver identity. Binding reads/writes that cell through Reflect only; position/scale/frames/animation/graphics and virtual calls stay typed. C++ generation explicitly verifies both owner-cell read/write dispatch and public method exports.

Inherited methods are skipped only when marked as generated by this macro and their resolved argument types, optional flags and return type match. Existing own fields, unmarked inherited collisions or incompatible types produce diagnostics. No arbitrary preexisting method name is assumed compatible, and no global source signature is substituted for Psych/native classes.

`NightmareVisionSpriteOwner` borrows an atlas callback with rebind/release/atlasFrames. Rebind changes IO, release breaks IO references and later requests diagnose the released owner. Receiver cells borrow that owner. Only loadFromSheet requests owner IO; the other four work on unbound or released-owner receivers. Integration owns provider/session lifetime and must bind eligible real objects, including group children and mixed native gameplay classes, through the selected source route.

Native guard correction: the original bind check used Reflect.hasField. Generated hxcpp instances have no __HasField override, and hx::Object::__HasField returns false; eval passing alone did not validate that guard. Binding now checks Type.getInstanceFields(Type.getClass(receiver)) for the kept nullable field, independent of its current value, then uses raw Reflect get/set. Generated C++ verifies the member table, raw read/write dispatch and absence of hasField in helper calls. Root's native gate also executed fresh-cell and inherited binding plus untargeted rejection; that runtime acceptance comes from the actual engine probe rather than C++ generation alone.

Targeted destructor cleanup clears only the borrowed receiver reference. An existing own destructor retains its source body inside try/catch, clearing after normal completion or escaping error and rethrowing the original error value. Top-level early returns get cleanup immediately before return; compound Void returns evaluate their original expression first. Nested function returns keep their own scope. Direct super.destroy calls preserve/restore the borrowed cell around parent success or throw so a child can finish source callbacks after a parent wrapper, including caught parent errors. Final outer cleanup then clears it. No global depth registry or extra destructor state fields are added. Native lexical super-in-local-function remains illegal; the macro does not make that source compile. A class without its own destructor gets a super-then-clear override only when an ancestor does not already supply generated cleanup. Clear is idempotent and never releases the shared provider.
